## 1. 项目全景

### 1.1 定位与核心循环

「模拟一部手机」的沉浸式多线互动叙事：玩家用消息、电话、朋友圈、群聊、相册、备忘录推进剧情；
三位男主同时找她，回复谁、何时回、回不回决定好感、flag 与结局。核心差异点是**已读不回的后果**与
**手机形态的叙事**，不是传统视觉小说的对话框。

- 主角：林夏（策展人）
- 路线：沈砚之 / 陆辞 / 江屿 / 独行线（真结局）
- 时间：起始 2025-07-15，21 天主线
- 结局：17 个（每男主 GOOD/NORMAL/BAD/HIDDEN，独行线 4 + 真结局）

## 3. 关键问题诊断

### 3.1 P1：主线节奏仍没有确定性保证

**链路**：`photo_rooftop` → `route_choice_night`（`advance_day` 到 23:00）→ `route_choice_msgs`
（`message_batch`，delay 1）→ `route_choice_trigger`（`route_choice`）。

**机制**（v0.7.8 仍未变）：

- `_queueEventDispatch` 用真实 `setTimeout`（400ms / 2.8s），不是虚拟时钟；
- `advanceTime` 只做 `_flushPendingEventDispatches`，队列是 **FIFO**，没有「主线优先」；
- `checkTimeEvents` 会把当前 day/hour 命中的所有事件一次性 `scheduleEvent`，日常事件可与主线链交错；
- 路线选择前没有 `routePending` 窗口锁。

**证据更新**：

- v0.7.5 测试报告 P2-1：加速跑测下路线选择可被推到 day10+；
- v0.7.6 修复后仍「未完全消除」；
- v0.7.7 巡检：自动通关 day10 进入沈砚之线并触发结局，**「完全不触发」的溃败已不复现**；
- 但 day10 仍晚于设计预期的 day4，且没有「路线选择 day≤4」断言。

**判断**：从 P0「流程可能卡死」降级为 **P1「节奏不确定」**。真实玩家正常节奏大概率 day4，
但快速推进/设备卡顿/后台切换仍可能改变顺序。

**建议**：

1. `_queueEventDispatch` 增加 `priority`（`critical` > `mainline` > `daily`），按 `(dueAt, priority)` 排序；
2. `route_choice_night` 派发时置 `state.flags._routePending = true`，`chooseRoute` 后清除；期间跳过 `soloOnly` 日常；
3. 路线选择弹窗出现时阻塞其他 choice 交互（复用 `pendingInteractions` 优先级）；
4. 增加「day4 路线选择」断言与 4 条路线全通测试（真实时钟 + 10 倍 + 100 倍三档）。

   扫描可见文本中的中文字符（用户自定义姓名/允许名单除外）；
4. 先修核心路径（路线选择、设置、结局图鉴、地点、塔罗、任务、回忆、男主视角），再修长尾；
5. 建立译名表与术语表（林夏/Lin Xia、沈砚之/Shen Yanzhi、陆辞/Lu Ci、江屿/Jiang Yu、霓城/Nicheng、雾港/Wugang），
   统一标点与引号；抽取 50 个关键场景人工抽检。

### 3.3 P1：男主线内容纵深不足

| 内容 | 独行线 | 三条男主线 |

**问题**：选线后 day7-14 没有角色专属的「日常感」内容，路线链又用 `advance_day`（「半个月后」「南方出差」）
做时间压缩，导致男主线更像「一条短链」而不是「21 天的手机生活」。这削弱了本作最大的差异点
（手机日常的陪伴感），也让三条线在体感上趋同。

2. 每条男主线补 day7-14 的 3 条专属日常（纯消息 / 至多 1 个 choice，避免抢主线）；
3. 共享 7 条 `inRoute` 事件用 `flavors` 做角色语气变体，避免三倍复制；
4. 每条线加 1 通电话、1 个约会场景、1 个专属收集品；新增 1 条 4 线索谜题链。

### 3.5 P1：三端发布产物仍不一致

| 平台 | 产物 | 首载 |
|---|---|---|
| 自有服务器 | `dist/`（单 bundle） | 快 |
| HF Space | `dist/`（单 bundle） | 快 |
| **GitHub Pages** | **仓库源码（61 脚本）** | **慢** |

同时：

- `deploy-server.yml` 与 `deploy-hf.yml` 各自 `npm ci` + 重复校验；`deploy.yml` 不构建；
- v0.7.8 的 `reusable-verify.yml` 合并方案因 GitHub Token 缺 `workflow` scope **被从历史剥离**，
  补丁在 `docs/patches/v0.7.8-workflow-merge.patch`，GitHub 端仍是旧版三工作流；
- 没有部署后自动校验：三端版本、bundle 哈希、关键资源是否 200；
- 自有服务器 2026-10-28 出现过整机级故障（sshd/nginx 全部失效，只剩 ICMP），现已加 systemd timer 告警，
  但仓库侧没有外部 uptime/版本漂移检查；
- HF Space 的 OG 已在 v0.7.8 修复为绝对地址；`HF_TOKEN` 仍是写权限长期 Token。

**建议**：

1. 抽 `build.yml`（reusable workflow）：`npm ci` → 全量校验 → `build_bundle` → 上传 artifact；
   需要带 `workflow` scope 的 Token 才能把补丁真正推上 GitHub；
2. 三端部署只消费 artifact：Pages 发 `dist/`，服务器 rsync `dist/`，HF 上传 `dist/`；
3. 新增 `tools/verify_deploy.mjs`：curl 三端，解析 `<meta name="version">` 与 `bundle.js` 哈希，
   与 `VERSION` 比对；部署后跑一次 + 每日 cron；
4. nginx 落 `Content-Security-Policy`（含 `frame-ancestors 'none'`）、`X-Frame-Options: DENY`、
   `Referrer-Policy`、`Permissions-Policy`；meta CSP 只作兜底；
5. HF Token 改细粒度（仅该 Space 写权限）；自定义域名可选。

**全 STORY 覆盖率统计口径**（本文使用，供后续工具化）：

- 递归遍历 `STORY`，收集 `text / prompt / desc / onSuccess / onFail / title / caption / meaning / how / name / label / note / summary`
  且长度 ≥2 的字符串；
- 与 `i18n/en-US.js` + 4 个 `story-en-translations*.js` 合并后的 `en-US` 包比对；
- 结果：1,178 条可见字符串，764 条有译文，414 条缺失，覆盖率 **64.9%**；
- 该口径包含专有名词（地点/牌名/结局名），若只算句子级文案比例会更高，但**缺口面一致**，足以说明英文模式不完整。

**UI 中文长尾统计口径**：

- 扫描 `ui/*.js`，剔除注释、HTML 片段、模板插值后，收集纯中文短文案；
- 20 个文件、约 136 处、129 条唯一文案未进 `en-US` 包；
- 设置页（`ui/22_settings.js`）整体未接 `t()`，是最典型样本。
