# v0.1.3 交互与延迟剧情恢复

## 问题

存档此前只恢复尚未送达的消息、链式事件和来电预约。事件已经展示给玩家后，路线选择、旁白选择、偶遇、响铃中的电话，以及梦境/梦魇界面仍依赖运行时变量或 DOM。读档会清理这些变量，已写入 `firedEvents` 的剧情无法再次出现。

“已读不回”后续、关系阶段临界事件和时间推进动画也使用内存定时器；读档会清理定时器，导致后续剧情或时间变化被吞掉。

## 修复

- 增加 `pendingInteraction`，持久化路线、旁白、偶遇与活动来电；读档后的 UI 按状态重新显示。
- 活动来电保存未接截止时间，读档后继续倒计时；梦境与梦魇按未完成状态恢复。
- 增加 `pendingFollowups` 与 `pendingTimeAdvances`，并让关系临界事件使用既有的持久化事件派发队列。
- 消息增加稳定 ID，使回复能够取消对应的待执行追问。
- `stopAutoSave()` 注销状态监听器，避免重复初始化后累积自动存档回调。

## 回归覆盖

`test_regressions.js` 覆盖保存后新实例读取并继续路线、旁白、偶遇、来电、梦境、追问、临界事件和时间推进，以及自动存档监听器的启停生命周期。
