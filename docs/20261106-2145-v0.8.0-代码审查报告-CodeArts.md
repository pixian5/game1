## 2. 问题清单

### P2-1 限时回复可被反复进出会话重置

**位置**：`ui/03_messages.js:126`、`ui/04_engine_events.js:110`、`ui/04_engine_events.js:126/155`

`openConversation` 每次打开带待选项的会话，都会调用 `showChatChoice`；该函数先 `clearTimeout(timeoutTimer)`，再按 `choice.timeout` **重新计时**。

**后果**：玩家只要在倒计时结束前退出再进入同一会话，限时就重新开始，所谓「30 秒未读不回 / 限时抉择」可以被无限刷新绕过。

**同类问题**：倒计时的 `deadline` 没有存入 `pendingChoice`，因此读档后也会重新计时。

**建议**：把 `dueAt` 写入 `pendingChoice`（或 `pendingInteractions`），渲染时按剩余时间显示进度；打开会话、读档恢复均不重置截止时间。

### P2-2 多会话共用一个 `timeoutTimer`，无法按会话取消

**位置**：`ui/04_engine_events.js:171-193`

`timeoutTimer` 是单值变量，`startTimeout` 直接覆盖。多个会话同时存在限时选项时，后一次会覆盖前一次的句柄；`clearTimeout(timeoutTimer)` 只能清理最新一个，旧计时器的 `onTimeout` 仍会执行。

**后果**：旧会话的「超时自动选默认项」可能在新会话之后触发，玩家看不到旧选项却被自动回复。

**建议**：改为 `Map<convId, {timer, dueAt}>`；在会话切换、读档、回复时按会话清理。

### P3-1 错误上报端点在非自有服务器上产生 404

**位置**：`pwa.js:15`

`navigator.sendBeacon('/collect-error?...')` 依赖自有服务器的 nginx 端点。部署到 HF Space、GitHub Pages、本地 `test_server.js` 时该端点不存在，前端每次异常都会额外产生一个 404。

**建议**：按部署环境启用上报（如仅 `oh.sbbz.tech:9443`），或对非自有源直接跳过，避免制造二次错误。

### P3-2 旁白选择缺少与聊天/群聊一致的空值防御

**位置**：`ui/04_engine_events.js:60-90`

v0.7.9 已为 `showChatChoice`、`showGroupChoice` 增加 `choice/options` 校验，但 `showNarratorChoice` 仍直接读取 `choice.prompt` 与 `choice.options`。

**建议**：补同样的防御，避免异常存档或数据错误导致渲染崩溃。

### P3-3 限时进度仅存于 UI 内存

`startTimeout` 的 `start` 是 `Date.now()` 局部变量，既不持久化也不随 `stateChange` 保存；刷新页面后进度条与截止时间都会重置。

**建议**：与 P2-1 一并处理，截止时间进入引擎状态并纳入存档。
