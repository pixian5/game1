## 三、任务清单（含验收标准）

### M1 公网账号服务上线（P0）

**N1.1 服务器侧部署账号服务**
- 动作：在目标服务器拉取仓库 → `cd server && ./ctl.sh start`（或 systemd unit）；
  `NH_SITE_ROOT` 指向 `dist/`；Node ≥ 22（`node:sqlite` 为内置模块，无 npm 依赖）。
- 数据：`server/data/game.db`、`server.log`、`server.pid`，目录必须在仓库外或已 gitignore。
- 验收：`curl https://<域名>/api/health` 返回 `{"ok":true,"database":"ok","version":"0.9.9"}`。
- 风险：容器重建丢库 → 上线前先配 `backup_db.mjs` 定时任务（见 N2.5）。

**N1.2 Nginx 反代与 HTTPS 头**
- 动作：`location /api/ { proxy_pass http://127.0.0.1:8095; proxy_set_header X-Forwarded-Proto $scheme; }`；
  静态仍由 Nginx 发 `dist/`。
- 验收：HTTPS 下 `Set-Cookie: nh_session=...; Secure; HttpOnly; SameSite=Lax` 正确下发；
  账号页不出现"服务不可用"。
- 风险：漏传 `X-Forwarded-Proto` → Cookie 不带 Secure，部分浏览器拒收。

**N1.3 构建产物与目录隔离**
- 动作：`node tools/build_bundle.mjs` 生成 `dist/`；确认 `server/ docs/ 经验/ tools/ .git/` 均 404。
- 验收：`curl https://<域名>/server/api.mjs` 返回 404；`dist/index.html` 版本号 v0.9.9。

**N1.4 线上全链路验收**
- 动作：注册 → 上传云存档（rev1）→ 刷新会话保持 → 第二浏览器登录 → 从云端恢复 → 注销。
- 验收：五步全部成功；注销后 `/api/account/export` 401；数据库四表无残留该账号。
- 产出：一份线上验收记录（截图 + 时间 + 版本号）写入 docs。

### M2 账号能力补强（P1）

**N2.1 邮件找回（可选）**
- 背景：当前找回依赖一次性找回码，码丢失只能注销。
- 动作：注册可选邮箱（不入库明文，仅存哈希或加密）；接 SMTP；`POST /api/auth/recover-by-email`。
- 验收：未填邮箱的账号仍走找回码（不破坏老用户）；填了邮箱可重置；邮件发送失败有降级提示。
- 注意：需要邮箱服务商与发信域名（决策点 D2）。

**N2.2 设备备注与活动时间**
- 动作：设备列表增加自定义备注（存 sessions 表 `label`）；显示"最后活跃：x 分钟前"。
- 验收：备注持久化；改密后其它设备被踢且列表实时更新。

**N2.3 安全审计可视化**
- 动作：账号页"最近安全记录"10 条（登录/改密/找回/注销/云存档冲突），来自 `audit_log`。
- 验收：只显示本人记录；注销后不可查。

**N2.4 并发压测**
- 动作：脚本模拟同账号 10 会话并发、云存档 409 竞争、SQLite 写锁、限流触发。
- 验收：无 500；409 语义正确；P95 < 300ms（本地容器）；输出压测报告。
- 风险：SQLite 单写锁在并发上传下排队 → 必要时切 WAL 已启用，仍受限则评估迁移 PostgreSQL（不推荐本轮）。

**N2.5 定时备份**
- 动作：`backup_db.mjs` 接入 cron（每日 03:00），保留 7 天，备份目录在仓库外。
- 验收：连续 3 天生成备份；恢复演练成功（用备份起服务读到旧数据）。

**N2.6 会话失效提示**
- 动作：改密/找回后其它设备下次请求返回 `session_revoked`，前端提示"账号已在其它设备修改密码"。
- 验收：双设备实测，旧设备不再静默 401。

### M3 质量与自动化（P1）

**N3.1 CI 流水线**
- 动作：仓库已有 GitHub Actions 被用户删除（历史决策），需先确认是否恢复（决策点 D3）；
  若不恢复，用服务器侧 cron 跑 `npm run test:all:offline`。
- 验收：每次 push 自动跑 check:version / check:ui / test:regressions / test:story / test:account-api，失败阻断。

**N3.2 覆盖率红线**
- 动作：`npm run test:cov`，引擎行覆盖 ≥ 60%；低于则补测试或调整阈值（需记录理由）。
- 验收：CI 输出覆盖率报告并存档。

**N3.3 三浏览器 E2E**
- 动作：在装有 Firefox/WebKit 内核的环境跑 `playwright test --project=firefox --project=webkit`。
- 验收：账号全流程与主流程在三内核通过；容器缺内核时明确跳过并标注。

**N3.4 账号 E2E 扩展**
- 动作：补 5 条：错误密码 5 次锁定、CSRF 拒绝、云存档 409 冲突、导出字段完整性、注销后数据清空。
- 验收：`npm run test:account` 6 条全绿。

**N3.5 离线测试集拆分**
- 动作：`test:all:offline`（无浏览器）与 `test:all`（含 E2E），CI 与本地各取所需。
- 验收：无浏览器环境下 `test:all:offline` 可全绿。

### M4 内容深化（P2）

**N4.1 独行线专属事件补齐**
- 现状：三条男主线各有专属事件，独行线明显偏薄，玩家走真结局线时日常重复度高。
- 动作：按现有 `story/01b~01d` 结构补 8-12 条独行线专属事件（day7-21），复用既有 flag 与关系值。
- 验收：`validate:story` 0 错；`test:story` 全绿；路线矩阵独行线格仍 100%；新增事件可达（用 `tools/reachability.mjs` 复核）。

**N4.2 day5 时间事件补齐**
- 现状：`validate:story` 警告 day5 时间事件仅 1 条。
- 动作：补 1-2 条 day5 时间事件，注意不侵入选线前节奏。
- 验收：警告清零（0 错 0 警）。

**N4.3 后期节奏与路线差异**
- 动作：day15 之后增加路线专属日常/冲突；控制通用事件重复率；每条线至少 2 个后期专属转折。
- 验收：按天统计事件重复率下降 ≥ 30%；三条线与独行线后期事件数量差 ≤ 20%。

**N4.4 英译收口**
- 动作：`tools/i18n-gap.mjs` 列出缺口（当前约 30 条 / 覆盖率约 96%），逐条补。
- 验收：缺口 0；`check:ui` i18n 覆盖 100%。

**N4.5 可达性复核**
- 动作：用 `tools/reachability.mjs` 复核三条男主线与独行线的不可达事件，清理或接线。
- 验收：不可达事件清单归零或有明确"预留"标注。

### M5 运维与一致性（P2）

**N5.1 三入口版本一致性巡检**
- 动作：`tools/live-check.mjs` 定时抓三个入口的 `<meta name="version">` 与 `/api/health`，不一致告警。
- 验收：巡检报告三入口 `versionMatch=true`。

**N5.2 三入口同步到 v0.9.9**
- 现状：GitHub Pages 旧版、Instabox v0.9.6、抱脸 v0.9.0。
- 动作：分别用 `dist/` 更新；Pages 注意 gh-pages 体积（历史 68MB → 18MB）。
- 验收：三入口打开均为 v0.9.9，账号卡片在支持的入口可用。

**N5.3 监控与告警**
- 动作：uptime 监控 `/api/health` 与首页；异常走 Bark（已有推送地址）。
- 验收：手动停服务 1 分钟内收到告警。

## 五、风险与回滚

| 风险 | 影响 | 预防 | 回滚 |
|---|---|---|---|
| SQLite 写锁在高并发下排队 | 云存档上传变慢/超时 | WAL 已开；压测先行；限制单账号并发 | 降级为"手动上传"，关闭自动同步 |
| 容器/服务器重建丢数据库 | 账号与云存档全丢 | N2.5 每日备份到仓库外 | 用最近备份恢复，公告维护 |
| SW 缓存回归导致登录态丢失 | 用户以为账号异常 | `check:ui` 已有 `/api` 守卫 + E2E 断言 | 强制 `CACHE_VERSION` 升级并清缓存 |
| CSP 阻断跨域 API | 账号页空白 | 同源部署为默认；跨域需同步 `connect-src` | 改回同源 |
| 凭据缺失（GitHub 推送） | 三远端不同步 | 用户提供 token 或本机推送 | 以 GitCode 为权威源，其余补推 |
| 内容改动破坏时序 | 剧情卡死/事件不发 | `test:route` + 矩阵先行，改后全跑 | 回滚对应 story 文件 |

## 六、需要用户拍板的决策点

1. **D1 账号服务放哪**：自有服务器 `oh.sbbz.tech:9443`（当前超时，需先恢复）／Instabox 沙箱／
   新 VPS。建议自有服务器 + Nginx 反代，数据掌握在自己手里。
2. **D2 是否接邮件找回**：需要 SMTP 账号与发信域名；不接则维持找回码（可接受）。
3. **D3 CI 平台**：GitHub Actions 此前被删除；是否恢复？不恢复则用服务器 cron。
4. **D4 推送凭据**：本容器无 GitHub 凭据，需用户提供 token（或在本机补推）。
5. **D5 v1.0 标准**：建议 = 线上账号可用 + 三入口一致 + 覆盖率 ≥60% + 英译 100% + 内容无警告。

## 七、明确不做

- 中国国内内容审核适配（作品面向海外发表）。
- 付费/内购体系（无商业化计划前不引入）。
- 多租户/多游戏平台化（当前单游戏自托管足够）。

## 八、接手提示（给下一个模型）

1. 先读 `docs/20261120-0333-当前开发进度-CodeArts.md` 与本文，再看 `经验/` 对应手册。
2. 任何改动前先跑 `node check_version.js && node check_ui.js && node test_regressions.js`，建立基线。
3. 账号相关改动必须同时跑 `node server/test_api.mjs`；前端改动跑 `npm run test:account`（需内核）。
4. 修改 `sw.js` 的 `/api` 排除逻辑会被 `check:ui` 守卫拦截，不要绕过。
5. 文档三件套 + `文档索引.md` + README 指针是硬规约，缺一即视为未交付。
