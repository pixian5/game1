### 二、升级过程（安全顺序）

1. 先把旧目录整体打包备份：`/data/home/game1-backup-202611191338.tar.gz`（19 MB）。
2. 检查发现旧目录里带有 **16 个文件的未提交本地改动**
   （`i18n/en-US.js`、`i18n/zh-CN.js`、`index.html`、`sw.js`、`ui/` 下多个文件等），
   因此**放弃 `git reset --hard`**，改为重新克隆到新目录 `/data/home/game1-new`，
   原目录保持原样不删。
3. 在新目录跑 `node tools/build_bundle.mjs`（零依赖，无需 `npm install`），
   产出 68 个源文件合并的单 bundle，总体积 3.84 MB。
4. 把 `dist/` 内容复制到独立站点根 `/data/home/site`，与源码目录分离。
5. **只**停掉 9090 端口的旧服务进程；同沙箱 8080 端口上另一个项目
   （「一刀999 · 百图征途」）的进程完全未受影响。
6. 在 `/data/home/site` 上以后台作业方式重启
   `python3 -m http.server 9090 --bind 0.0.0.0`。
7. 重新跑 `tools/live-check.mjs` 验收。

### 三、踩坑记录

- **旧部署用仓库根目录当站点根**，会一次性串行请求 68 个脚本，
  首屏明显变慢；正确做法永远只发布 `dist/`。
- **沙箱里的仓库不是干净的**，有 16 个文件的本地改动。任何接手的人如果
  直接 `git reset --hard origin/main`，这些改动会被静默丢弃。
- **端口有他人在用**：8080 属于另一个项目，9090 才是本项目的。
  `pkill -f 'http.server'` 这种宽泛写法会误杀别人的服务，
  必须写成 `pkill -f 'http.server 9090'`。
- **Instabox 命令行工具的安装方式是官方脚本**，不是 `pipx`：
  `curl -fsSL https://instabox.sh/install.sh | sh`，或 `npm install -g instabox`。
