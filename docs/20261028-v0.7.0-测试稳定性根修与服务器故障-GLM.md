# v0.7.0 测试稳定性根修 + 服务器故障记录（2026-10-28 · GLM）

## 一、测试偶发失败的根因与修复（已完成）

### 取证过程

此前多次 `test:all` 链式运行时偶发失败，但单独跑 `test_regressions.js` 连跑 10 次全过。
抓取第 1 次失败日志后真相大白——**不是 regressions，是 E2E**：

```
playwright/smoke.spec.js:110 › 角色头像在聊天/通讯录加载（v0.2.6）
Error: expect(received).toBe(expected)
Expected: 128  Received: 0
  at chatAvatar.evaluate(i => i.naturalWidth)
```

### 根因

头像 `<img>` 带 `loading="lazy"`。测试在设置 `src` 后立刻读 `naturalWidth`，
若那一刻图片尚未解码完成，`naturalWidth` 就是 **0**。图片小（8KB）时多半已解码 → 通过；
机器负载高或缓存冷时 → 偶发失败。**属于测试时序缺陷，不是产品 bug。**

### 修复

三处头像断言（聊天头像 / 档案头像 / 朋友圈头像）从「同步读 naturalWidth」
改为 `waitForFunction(() => img.complete && img.naturalWidth === 128, {timeout: 10000})`。

### 验证

`npm run test:all` **连跑 5 次，5/5 通过（0 失败）**。这个从阶段 E 起反复干扰发布流程的
偶发问题至此根除。

## 二、服务器故障（v0.7.0 部署未完成）

### 现象

| 检查项 | 结果 |
|---|---|
| ICMP ping | ✅ 通（232-352ms） |
| 代理端口 80 / 443 / 2053 / 2083 / 8443 | ✅ 全部 OPEN |
| **SSH 2424** | ❌ TCP 能连，但 `kex_exchange_identification: Connection closed by remote host`（不返回 banner） |
| **网站 9443** | ❌ TCP 能连，TLS 握手收到 EOF（`unexpected eof while reading`） |
| GitHub Pages 备份线 | ✅ 正常，已是 v0.7.0 |

### 最终诊断（复查后恶化）

初查时代理端口 80/443/2053/2083/8443 尚能建立 TCP 连接；**复查时应用层已全部失效**：

| 端口 | 服务 | TCP | 应用层 |
|---|---|---|---|
| 22 | sshd（原生） | OPEN | ❌ 无 banner（`kex_exchange_identification` 断开） |
| 2424 | sshd（自定义） | OPEN | ❌ 无 banner |
| 80 | xbz 代理 | OPEN | ❌ HTTP 000 |
| 443 | bz 代理 | OPEN | ❌ HTTPS 000 |
| 9443 | nginx（本站） | OPEN | ❌ TLS EOF |
| ICMP | 内核网络栈 | — | ✅ 通（230-293ms） |

**结论：只有内核网络栈（ICMP）还活着，所有用户态服务的握手全部失败。**
这不是单点故障（不是只有 nginx 挂了），而是**整机级故障**：进程被 OOM killer 批量杀死、
磁盘写满导致服务全面崩溃、或系统进入某种只读/异常状态。

### 判断

服务器**整机在线**（网络层健康、代理服务健康），但 **sshd 与 nginx 两个进程失效**——
两者都已不再完成各自协议的握手。最常见原因是**磁盘写满**（日志/rsync 累积），
或这两个服务进程崩溃/OOM 被杀。

注意：本次部署中 rsync 两次以 `unexpected end of file` 中断，可能写入了不完整的
`/var/www/neon-heart`，但这不会影响 nginx 进程本身的存活。

### 待办（需用户操作）

本机没有 AWS CLI/凭证，无法远程重启。请任选其一：

1. **云控制台重启实例**（AWS EC2 → 实例 → 重启）——**首选方案**，整机级故障只能从控制台恢复
2. 若能 SSH 进（换网络/换跳板），执行：
   ```bash
   df -h                    # 查磁盘
   systemctl status nginx sshd
   journalctl -u nginx -n 50 --no-pager
   du -sh /var/log/* | sort -h | tail
   ```
3. 恢复后我这边执行 `bash deploy.sh` 补部署 v0.7.0（已在三远端就绪）

### 影响面

- 主入口 https://oh.sbbz.tech:9443/ 暂时不可用
- **GitHub Pages 备份线正常**（https://pixian5.github.io/game1/ 已是 v0.7.0），玩家可正常游玩
- 代码、存档格式、三远端均无影响

## 三、v0.7.1：服务器不可用期间的内容均衡推进

主入口故障期间，继续做不依赖服务器的打磨。发现并修复了一处内容不均衡：

**问题**：三条男主线的二周目变体分布不均——沈砚之/陆辞/江屿各只有 **1 个**，且都集中在单一节点。

**修复**：为三条线各补一个中段情感节点的二周目版本：

| 线 | 新变体 | 二周目视角 |
|---|---|---|
| 陆辞 | 米兰道别 | 「上一次我就这样说了然后真的走了」→ 这次把话说完，并告知退票手续费已查好 |
| 江屿 | 试登台 | 「上一次我停在副歌前」→ 这次想知道知道你在台下能不能唱完 |
| 沈砚之 | 朋友的警告 | 「这话我上一次也说过」→ 不问对错，只问你还想不想被"过滤"掉 |

三个变体均保留原选项分支与后续落点（不影响结局判定），双语同步至 **745/745 = 100%**。
新增回归用例 2 条：变体数量均衡检查、二周目改道与一周目直通。

**实测**：三变体在 ngPlus 下正确改道且不触发原事件；一周目直通原事件不受影响。
