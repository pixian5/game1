# v0.4.5：自有服务器部署补全（2026-10-24 15:35 · DeepSeek-V4.1-Flash）

## 一、问题

线上主入口 `https://oh.sbbz.tech:9443/` 还停在 **v0.1.14**，而仓库已到 v0.4.4。
检查 `deploy.sh` 发现部署清单漏了两项：

- `i18n/`（v0.3.6 引入的语言包，`index.html` 有 3 个 script 依赖）
- `privacy.html`（v0.3.7 引入的隐私说明页，首页链接指向它）

直接跑旧脚本会让线上缺语言包与隐私页：`i18n/*.js` 404、隐私链接打不开，
且 `--delete` 还会把服务器上此前手动放的副本一并删掉。

## 二、改动

`deploy.sh` 的 rsync 清单补上 `privacy.html` 与 `i18n`：

```bash
index.html privacy.html manifest.json sw.js pwa.js types.js style.css audio.js \
story i18n interaction_queue.js save_migrations.js engine.js engine_social.js \
engine_content.js engine_progress.js engine_save.js \
ui assets \
```

核对方式：把 `index.html` 里所有本地 `src` / `href` 抽出来，按目录去重，
与 rsync 清单逐项对齐（结果是 `assets / i18n / story / ui` 四个目录 +
`audio.js / engine_*.js / interaction_queue.js / manifest.json / privacy.html /
pwa.js / save_migrations.js / style.css` 八个单文件，全部覆盖）。

## 三、验证

- 本机：`npm run test:all` 全绿（46 回归 / 294 剧情 / 12 E2E），版本校验 0.4.5。
- 线上：`curl -sk https://oh.sbbz.tech:9443/` 标题为 v0.4.5；
  `i18n/index.js`、`privacy.html`、`assets/og-cover.jpg` 均返回 200；
  `sw.js` 的 `CACHE_VERSION` 为 `neon-heart-v0.4.5`（旧用户会因缓存名变化自动更新）。

## 四、经验

1. **部署脚本清单必须与 `index.html` 依赖对齐**，新增顶层目录（`i18n/`）或新页面
   （`privacy.html`）时，`deploy.sh` 是最容易漏改的地方；`check_ui.js` 只校验仓库内引用，
   管不到部署清单。
2. **rsync `--delete` 是双向风险**：清单漏项会删掉服务器上的对应目录；
   部署前先在本机把清单与引用清单做一次差集，比事后救火便宜。
3. 服务器版本落后太多时（v0.1.14 → v0.4.5），一次 `--delete` 全量覆盖即可，
   无需增量补丁；存档在浏览器 localStorage，不在服务器，不受影响。
