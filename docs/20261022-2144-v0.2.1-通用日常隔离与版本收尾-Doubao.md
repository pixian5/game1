## 二、回归事故：test:story 294 → 291

- **现象**：story 测试 3 项失败（结局触发 / 游戏已结束 / 已记录结局），v0.1.14 为 294/294 全过；
- **根因**：day7-10 通用日常事件为**无条件时间触发**（`trigger:{day,hour}`），男主线（如沈砚之线）
  剧情推进跨过 day7-10 时被 checkTimeEvents 派发。其中 `week1_review` 自带 choice，与最终抉择
  choice 同时挂起，测试的 `doAnyChoice` 匹配到前者（实际选中「这一周认识了三个人，不错」），
  选择后 `__shenyan_end_judge` 永远等不到 → 结局 3 项断言失败；
- **证据**：诊断日志尾部可见 `day7_shenyan_evening`（「布展方案通过了。今晚不留下来加班？」）
  消息乱入沈砚之控制线剧情——真实玩家同样会在结局前收到不相干的日常消息与选择。

## 三、修复方案：trigger.soloOnly 线路隔离

通用日常事件（含雨天闺蜜剧情）只在**未进入男主线**（route 为 null 或 `'solo'` 独行线）时触发：

1. `engine.js checkTimeEvents`：`evt.trigger.soloOnly && inRoute` 时跳过（inRoute = route 非空且非 solo）；
2. `engine.js _checkTimeEventsForRange`（睡眠跨小时补查路径）：同口径过滤，防止补查时再次泄漏；
3. `engine.js checkRainEvents`：男主线直接 return；
4. `story/01_events.js`：6 个 day7-10 事件 trigger 加 `soloOnly:true`；
5. `test_regressions.js` +1 条：男主线（shenyan）不派发 week1_review / 雨天剧情，
   独行线与未选线正常派发——按「按设计应该工作的路径必须有自动化用例钉住」的教训留档。

`checkGroupDinner` 保持无条件：聚餐投票（day6 群聊）本身对所有玩家发生，现场是投票的
连贯后续，且为群聊消息（无 choice、不阻塞主线），不属隔离范围。

## 五、经验教训

1. **新增时间触发事件必须先问「发生在哪条线路」**：男主线是线性叙事，通用日常无条件插入
   会破坏沉浸（本次直接造成结局段消息/选择乱入）；
2. **带 choice 的通用事件是高风险形态**：自动测试的「任意选择」会误选同类型 choice，
   玩家也会同时看到两段不相干选择；要么事件隔离（本次方案），要么测试选择器更精确；
3. **回归要先跑后提交**：v0.2.0 大轮改动若在提交前先跑 test:all，问题不会带进提交历史；
4. **前端错误上报依赖部署侧**：`/collect-error` 需要 nginx 配置配合，已列入待办确认。
