# 账号系统与云存档（v0.9.8 → v0.9.9 · 2026-11-20 03:33 · CodeArts）

## 一、目标与边界

本轮在容器 `/home/user/code/game1` 内给《霓虹心事》补一套**完整、可自托管**的账号系统：

- 注册 / 登录 / 会话保持 / 退出
- 忘记密码：一次性找回码重置（无邮箱、无 SMTP）
- 改密（踢掉其它设备）、设备列表、单设备退出
- 昵称修改
- 账号数据导出
- 注销账号（级联清空云端数据与会话）
- 4 槽云存档整包上传 / 恢复 / revision 冲突二选一 / 自动同步
- 限流、CSRF、安全审计、中英双语 UI、隐私说明改写

明确不做：itch.io 上架（用户本轮指示“先不管”）。游戏本体仍可在无账号、无网络时离线玩。

## 二、总体架构

```
浏览器（纯前端）
  ├─ 静态站点 index.html + ui/*.js（无构建）
  ├─ ui/25_account.js  设置页内嵌账号/云存档卡片
  └─ fetch /api/*（同源，Cookie 会话）
          │
Node 22 服务（server/）
  ├─ index.mjs  同一个端口发静态 + /api
  ├─ api.mjs    路由、CSRF、限流、错误码
  ├─ auth.mjs   scrypt、token、找回码、Cookie、LoginGuard
  ├─ db.mjs     node:sqlite（WAL、外键、迁移、审计清理）
  └─ data/      game.db / server.log / server.pid（gitignore）
```

选择“同源单进程”的原因：Cookie 不需要 CORS，部署只需要一个端口；静态目录黑名单可直接挡住
`server/`、`docs/`、`tools/`、`.git` 等敏感路径。

## 三、数据模型

SQLite 四张表：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, username, username_lower, nickname, pwd_hash, pwd_salt, recovery_hash, recovery_salt, created_at, updated_at, last_login_at | 用户名大小写不敏感唯一；密码与找回码只存 scrypt 哈希 |
| `sessions` | id, user_id, token_hash, created_at, expires_at, last_seen_at, ua, ip | token 只存 SHA-256；30 天过期；单账号最多 10 台 |
| `saves` | user_id, data, bytes, revision, updated_at, client_updated_at, device | 4 槽整包 JSON；`revision` 做冲突检测 |
| `audit_log` | id, user_id, action, detail, ip, created_at | 90 天清理；注销时按 user_id 清空 |

外键：`sessions` / `saves` 对 `users` 为 `ON DELETE CASCADE`；`audit_log` 不设外键，注销时显式清理。

## 四、API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查；返回版本与数据库状态 |
| POST | `/api/auth/register` | 注册，返回 user + 一次性找回码 + 会话 Cookie |
| POST | `/api/auth/login` | 登录；同用户名+IP 5 次失败锁 15 分钟 |
| POST | `/api/auth/logout` | 退出当前会话 |
| GET | `/api/auth/me` | 未登录返回 `200 {user:null}`，避免控制台 401 |
| POST | `/api/auth/recover` | 用户名 + 找回码重置密码；清空全部会话 |
| PATCH | `/api/account/profile` | 改昵称 |
| POST | `/api/account/password` | 改密；校验当前密码；踢其它设备；10 次/15 分钟限流 |
| POST | `/api/account/recovery-code` | 重生成找回码；10 次/15 分钟限流 |
| GET | `/api/account/sessions` | 设备列表（UA、IP、最近活动、是否当前） |
| DELETE | `/api/account/sessions/:id` | 退出指定设备（当前设备则清 Cookie） |
| GET | `/api/account/export` | 导出资料 + 云存档 + 会话 + 最近 200 条安全记录 |

| GET | `/api/saves` | 取云存档整包 |
| PUT | `/api/saves` | 上传整包；带 `baseRevision`，不匹配且非 `force` 返回 409 |

invalid_credentials / locked_out / rate_limited / invalid_recovery / unauthenticated /
save_conflict / saves_too_large / invalid_saves / save_corrupted / csrf_blocked /
json_required / internal_error / network`。

## 五、安全设计

- **密码**：scrypt `N=16384, r=8, p=1`，随机盐；比较用 `timingSafeEqual`。
- **会话 token**：32 字节随机；只存 SHA-256；Cookie `nh_session` 为 HttpOnly + SameSite=Lax，
  30 天；HTTPS 判定兼容 `x-forwarded-proto / x-forwarded-scheme / x-scheme`。
- **CSRF**：所有非 GET 请求必须带 `X-Requested-With: neon-account`；有 Origin 时校验
  Origin 的 host 必须等于 `Host` 或 `X-Forwarded-Host`。
- **限流**：注册 10/小时/IP；登录 30/分/IP；找回 10/15 分钟/IP；改密与找回码重生成
  10 次/15 分钟/账号。`LoginGuard` 对“同用户名+IP”连续 5 次失败锁 15 分钟。
- **会话上限**：单账号 10 个，超出踢最旧。
- **静态隔离**：`server/ docs/ 经验/ tools/ deploy/ playwright/ node_modules/ .git/
  .handoff/ qa-shots/ dist/ patches/` 与 `test_*.js`、`README.md`、`package*.json` 等
  一律 404；路径穿越校验。
- **注销隐私**：先 `deleteAuditForUser(uid)` 再删用户；四张表均不留该账号数据。

## 六、云存档语义

- 云端是**整包 4 槽**（`auto/slot1/slot2/slot3`），不是逐槽合并；恢复时整包替换本机。
- 本机 `neon_cloud_meta:<username>` 保存 `{revision, updatedAt, saveTime, syncedAt}` 作为上传基线。
  新设备**不会**自动用服务端 revision 填基线，避免“新设备无冲突覆盖云端”。
- 上传带 `baseRevision`：
  - 与云端当前 revision 一致 → 成功，revision+1；
  - 不一致且未 `force` → 409 `save_conflict`，前端给“云端覆盖本机 / 本机覆盖云端”二选一；
  - `force` → 强制覆盖。
- 自动同步：监听 `gameSaved` + 30 秒轮询（自动存档 `silent` 不发事件），6 秒防抖；
  冲突时暂停自动同步并提示。
- 恢复前二次确认；`engine.applyCloudSaves()` 做逐槽迁移清洗，成功后若有 `auto` 则加载，
  并刷新存档页。

## 七、前端 UI

`ui/25_account.js` 挂在设置页末尾（`ui/22_settings.js` 调 `AccountUI.mount(body)`）：

- 未登录：登录 / 注册 / 找回三视图；注册成功展示一次性找回码，必须点“我已保存，进入账号”。
- 已登录：头像、昵称、@用户名、注册时间；云端 rev、更新时间、本机槽位数、上次同步；
  上传 / 从云端恢复 / 刷新；自动同步开关；冲突二选一。
- 账号管理：改昵称、改密、重生成找回码、设备列表与退出、导出账号数据、注销（勾选 + 密码）。
- 服务不可用：显示“账号服务暂时不可用，本地存档不受影响”，提供重连；不阻断游戏。
- 所有错误码先映射中文再走 `t()`；中英各新增 104 条文案。

## 八、本轮修复的关键 Bug

1. **Service Worker 缓存 `/api` 导致刷新后登录态丢失（最严重）**
   `sw.js` 原对所有同源 GET 走 cache-first，`/api/auth/me` 的游客响应被写进 Cache Storage；
   登录后刷新仍拿到旧的 `{user:null}`。修复：`url.pathname.startsWith('/api/')` 直接 return；
   `check_ui.js` 增加源码守卫；账号 E2E 在刷新前强制等待 `navigator.serviceWorker.controller`。
2. `LoginGuard` 把 `until=0` 误判为已过期并清空计数，导致 5 次失败永不锁定 → 只在 `until>0` 且到期时清。
3. 前端 `request()` 原只在有 body 时带 `X-Requested-With`，无 body 的 `DELETE /sessions/:id` 被 CSRF 拦 403
   → 所有非 GET 都带。
4. 注册后 `render()` 先判 `!state.me`，已登录直接进账号页，看不到找回码 → 优先 `view==='registered' && recoveryCode`。
5. `boot()` 的 `/me` 迟到响应覆盖用户刚完成的注册/登录 → 增加 `state.authRev` 计数，变化则丢弃。
6. 密码/找回码重生成缺少按账号限流 → 增加 10 次/15 分钟。
7. 注销后审计记录残留可关联 user_id → 注销前按 user_id 清空。

## 十、已知限制

- 没有邮件服务，找回依赖一次性找回码；找回码丢失只能注销重注册。
- 云端存档是整包覆盖，不做逐槽合并；两台设备同时改不同槽仍会冲突。
- 容器不持久：数据库、日志在 `server/data/`（gitignore），容器重建会丢；重要数据需
  `node server/backup_db.mjs` 备份到仓库外。
- 公网静态入口（`oh.sbbz.tech`）尚未接账号 API；当前完整服务只在容器 8095。
