# v0.2.2：塔罗 hint 文案变体（2026-10-22 22:29 · Doubao）

## 一、目标

v0.2.0 已把塔罗 hint 落地为**玩法**（「遇见」补偶遇、「好运」购物折扣）。本版补上待办
P1 的「**hint 类型对日常事件的文案变体**」：今日抽到的牌面运势类型，会改变中后期日常
消息的文案与语气（如「幸运」日苏苏八卦消息语气不同），让塔罗从"数值影响"进一步
产生"叙事影响"，增强每日抽牌的仪式感。

## 二、机制设计：消息级 flavors 变体（数据驱动）

- 消息对象可选新增字段 `flavors: { hintType: '替代文本', ... }`（逐条消息可配）；
- 引擎新增 `_fortuneType()`（engine.js）：读取今日牌面 hint.type（非当日/无牌面返回 null）；
- 引擎新增 `_flavoredText(msg)`（engine_social.js）：今日 hint.type 命中 `flavors` 键时
  返回变体文本，否则用默认 `text`；
- `queueMessage` 与 `queueGroupMessage` 的文本统一走 `_flavoredText`（入队即生效，
  typing 时间按变体文本长度计算）；
- 兼容性：无 flavors / 无牌面 / 非当日 → 一律走默认文本，既有事件与测试零影响。

## 三、文案覆盖（story/01_events.js，5 事件 10 条消息）

| 事件 | 变体类型 | 示例 |

语义在玩法层已落地，结局提示不宜剧透）。choice 事件（雨天/周评）只变消息文本，选项不变。

## 四、测试与验证

- 回归测试 +2：`_flavoredText` 命中/未命中/无 flavors/非当日四态；luck 日苏苏八卦数据层
  变体存在且默认文本保留；
- 踩坑：`newGame()` 已入队开场消息（苏苏「林夏！！！你到霓城了吗？？」），断言取入队后
  新增消息须记录入队前长度再取尾部，不能按 from 查找（会误命中开场消息）；
- 全量校验：validate:story 0 错 0 警 · lint 通过 · test:regressions 28/28 ·
  test:story 294/294 · check:ui 通过；E2E 在收尾阶段跑（test:all）。

## 五、经验

1. **叙事层影响比数值层影响更"可见"**：玩家能直接感知抽牌→文案变化的因果，是塔罗
   系统的低成本高感知增强；
2. **flavors 数据驱动**：不改消息结构（text 仍是默认），校验器零改动、既有测试零破坏；
3. **choice 事件变体只动文本**：选项的 thenEvent/flags 是剧情主干，变体不应复制选项。
