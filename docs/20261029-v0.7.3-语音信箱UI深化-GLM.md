# v0.7.3 语音信箱 UI 深化（2026-10-29 · GLM）

> 语音信箱是玩家通关过程中会自然攒起来的常驻功能：7 个来电事件里，未接/拒接都会留一条留言，
> 一周目走完通常有 6~7 条。但它的界面从 v0.1 起就没再动过——一行摘要 + 两个小按钮。
> 本轮把它补成一个「能听、能看全、能管理」的功能。

## 一、动手前摸底发现的四个问题

| # | 问题 | 性质 |
|---|---|---|
| 1 | `.voicemail-item` 样式写了 `cursor:pointer`，但**整条没有绑定任何事件** | 交互死区：大片区域点了没反应，只有两个小按钮可用 |
| 2 | 剧情数据里的时长标记（`（语音信箱 23"）`）被当作**正文**显示，秒数信息完全浪费 | 数据未利用：明明有真实时长，界面却只能显示摘要 |
| 3 | 留言正文直接 `escapeHtml(vm.text)` 输出，**没过 i18n 关口** | 英文模式下整段是中文原文 |
| 4 | `#badge-phone` 在 DOM 里存在，但全项目**没有任何 JS 写过它** | 死元素：语音信箱有未听留言时，主屏电话图标毫无提示 |

## 二、本轮实现

### 2.1 数据层：把秒数解析出来（`engine_social.js`）

剧情里 7 通电话有 6 条留言自带时长标记，第 7 条（`jiangyu_call_night`）的末句是普通台词。

```js
parseVoicemailMeta('（语音信箱 23"）：展签译名……算了。晚安。')
// → { durationSec: 23, body: '展签译名……算了。晚安。' }
```

- 正则同时认中文 `（语音信箱 23"）` 与英译包里的 `(Voicemail 23"):`
- 没有标记时按正文长度兜底估算（中文 5.5 字/秒、西文 2.6 词/秒 + 1.5s 起手），
  夹在 3~60 秒之间——保证任何留言都有合理时长，UI 永远拿不到 0 / NaN
- `durationSec` **不写入存档**：`_sanitizeLoadedState` 读档时用文本重算，
  老存档不做迁移也能立刻拿到时长

### 2.2 新增引擎接口

| 方法 | 作用 |
|---|---|
| `unreadVoicemailCount()` | 未听条数（App 徽标 / tab 红点数据源） |
| `markVoicemailRead(id)` | 单条标记已听，已听过返回 `false` |
| `markAllVoicemailsRead()` | 批量标记，返回实际改动条数 |
| `deleteVoicemail(id)` | 从列表移除并 emit `voicemailDeleted` |

### 2.3 播放沉浸感（`audio.js` + UI）

项目约束是「音频纯 WebAudio 合成、零素材」，所以不做语音合成，只做**听感暗示**：

- 锯齿波声源（基频按角色分：沈砚之 116Hz、陆屿 124Hz、江屿 134Hz、苏苏 196Hz）
- 两路带通滤波模拟元音共振峰（F1 700Hz / F2 1300Hz）
- 3.2Hz 音节包络 + 0.7Hz 呼吸起伏 → 听起来像「有人在说话，一顿一顿的」
- 一路极低音量低通噪声做线路底噪
- 起播/播完各一个短促电子音（`vmStart` / `vmEnd`），与线路声区分
- 音效总开关关闭时 `startVoicemail()` 返回 `false`，**UI 照常走进度**，视觉不受音频开关影响

界面上：34 根波形条（高度用留言 id 作种子生成，同一条每次打开一致、不会闪），
播放时按进度点亮 + 白色播放头；进度条可点击跳转；支持暂停/继续；
离开屏幕、切换 tab、关闭抽屉都会自动停播（`showScreen` 与 `closeVmDetail` 各兜一道）。

### 2.4 详情抽屉

点整条任意位置打开（修掉交互死区），内容：角色头像/名字、第几天几点、总时长、
波形+进度、完整正文（不再被 `-webkit-line-clamp:2` 截断）、操作区。

删除做**二次确认**：首次点击变成「确认删除？」，3.5 秒无操作自动复原，避免误触掉一条不可恢复的剧情留言。

### 2.5 未读体系

- 主屏电话图标徽标（`#badge-phone`）显示未听条数，挂进统一的 `updateBadges()` 入口，
  读档/开局/收到新留言都会刷新
- 语音信箱 tab 上的红点
- 列表内「全部 / 未听」筛选 + 「全部标为已听」批量操作

### 2.6 双语

新增 23 条 UI 词条，zh-CN / en-US 同步，`check:ui` 校验 **70/70** 全通过。

同时修掉一个**顺序陷阱**：剧情翻译包的 key 是「含前缀的完整原文」
（`（语音信箱 6"）：……霓城没雾。晚安。`），所以必须**先整条翻译、再剥前缀**。
反过来先剥前缀，永远查不到译文——第一版就是这么写的，英文模式下正文仍是中文，截图后才看出来。

## 四、顺手修的两处

1. **`tools/flow_test.mjs` 与 `tools/soak_test.mjs` 硬编码绝对路径**
   `import pw from '/Users/x/code/game1/node_modules/@playwright/test/index.js'`
   —— 换任何机器（含 CI）跑 `npm run flow:test` 都是 `ERR_MODULE_NOT_FOUND`。
   已改为按包名 `import { chromium } from '@playwright/test'`。
2. `#badge-phone` 死元素（见 1.4），随未读体系一起启用。

## 五、遗留

- **角色名 UI 标签仍是中文**（聊天列表、语音信箱详情等所有 `char.name` 出口）。
  译名约定（Lin Xia / Shen Yanzhi / Lu Ci / Jiang Yu / Su Su）目前只落在剧情正文里，
  界面标签还没接入——要做需要在 i18n 包补 8 个角色名映射并统一替换所有出口，属于全局改动，建议单独一轮。
- 语音信箱正文的英文来自 `story-en-translations-*.js`，只覆盖已录入的剧情句；
  未来新增留言若无译文会回退中文（i18n 框架的既有行为）。
