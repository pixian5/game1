## 三、执行原则（延续既有约定）

1. **版本**：每轮源码修改 `+0.0.1` 满十进一（v0.2.4 → v0.2.5 → … → v0.3.0），五处同步 + check:version；
2. **门禁**：修改完必须跑通全量 `npm run test:all`（E2E 用本机 Chrome）再停；
3. **文档**：每轮 docs 三件套 + README「当前开发进度/下一步待实现」+ 文档索引同步；
4. **提交**：中文 commit，推送 gitee + github 双远端；
5. **本地约束**：无流量期间禁用一切下载（npm/Playwright/镜像/远程部署），只用本地
   Docker 缓存、PIL、本机 Chrome；
6. **服务器**：部署类任务（M2.4）等流量恢复后执行，先本地完成全部可离线工作。

## 四、风险与应对

| 风险 | 应对 |
|---|---|
| 无流量阻塞图像 API 路线 | 走本地 PIL 路线（M1），图像 API 标记为"流量恢复后的可选项" |
| i18n 改动面大、易破坏剧情测试 | 只做结构抽取不动逻辑；validate:story 与 test:story 294 为硬门禁 |
| 音频参数凭感觉调 | M3.3 以用户实机听感为准，逐项记录参数变更前后对比 |
| github 推送偶发网络错误 | 重试机制（本轮已遇到一次，重试成功） |

## 五、本方案落地顺序建议

1. **先做 M1.1**（照片真实化）：纯本地、见效快、后续 M1 系列共用同一生成管线；
2. M1 系列完成后自然进入 v0.3.0（首个"视觉版"里程碑，可做一次完整视觉走查与截图存档）；
3. M2 的 2.1-2.3 可离线推进（i18n/SEO/隐私），2.4 等流量；
4. M3 与 M1/M2 无硬依赖，可穿插在版本间隙推进。
