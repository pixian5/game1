## Global Constraints（沿用项目约定）

- 版本 `+0.0.1` 满十进一；升版只用 `python3 tools/bump_version.py`；以 `check:version` 为准。
- 门禁：每轮 `npm run test:all` 全绿；E2E 无系统 Chrome 时用缓存 chromium 的**外部临时配置**，
  不改仓库 `playwright.config.js`。
- 文档：每轮 docs 三件套 + README + `文档索引.md`。
- 数据铁律：新增日常「纯消息、无 choice、无 effects」；`trigger` 四态；改 `computeEnding`/
  谜题必同步断言。
- 推送：`origin`（atomgit）；可用凭据为 PAT（`xRF8cXTx…` 一类，`ag` 登录 token 不可用于 push）。
- 工作目录可能被平台重置：每轮先 `git fetch && git reset --hard origin/main`。

## 三、详细任务计划

### 阶段 D1：无障碍与可达性（本地可做，建议 v0.4.0 ~ v0.4.2）

现状：`index.html` 仅 2 处 `aria-*`；`ui/` 无键盘事件；`tabindex`/`role`/焦点管理基本缺失。

#### Task D1.1：键盘可玩基础（建议 v0.4.0）

**Files:**
- Modify: `ui/01_input_delegate.js`（全局键盘委托）+ `ui/00_shell.js`（`showScreen` 后聚焦）
- Modify: `index.html`（给可交互元素补 `tabindex`/`role="button"`）
- Test: `playwright/smoke.spec.js`（新增键盘用例）

**Interfaces:**
- 复用既有 `showScreen(name)`、`data-action`、`data-back`、`[data-app]` 委托机制（无需新 API）。

- [ ] **Step 1: 写失败测试**（`smoke.spec.js`）：
```js
test('键盘可解锁并进入消息（v0.4.0）', async ({page}) => {
  await page.goto('/');
  await page.keyboard.press('Enter');            // 锁屏可回车解锁
  await expect(page.locator('#home-screen')).toHaveClass(/active/);
  await page.keyboard.press('Tab');              // 焦点进入 App 网格
  await expect(page.locator('#app-grid')).toBeFocused().catch(()=>{});
});
```
- [ ] **Step 2: 运行确认失败**：`npx playwright test -g "键盘可解锁"`（预期失败）
- [ ] **Step 3: 最小实现**：在 `ui/01_input_delegate.js` 加 `document.addEventListener('keydown')`：
  `Enter/Space` → 触发当前 `[data-back]`/已聚焦 `[data-action]`/锁屏；`Escape` → 返回上一屏
  （复用既有 `data-back` 逻辑）。
- [ ] **Step 4: 运行确认通过**；`npm run test:all`。
- [ ] **Step 5: 提交**：`bump → test:all → git commit/push`。

**验收**：锁屏可用键盘解锁；`Esc` 可返回；`test:all` 全绿。

#### Task D1.2：语义与 ARIA（建议 v0.4.1）

**Files:** Modify `index.html`（`role`/`aria-label`/`aria-live`）、`ui/*.js`（动态内容加
`aria-live="polite"`，如 `#toast`、消息列表）、`style.css`（`:focus-visible` 焦点样式）。
- [ ] Step 1：给 App 图标、返回键、发送按钮加 `aria-label`；消息流容器加 `role="log"`
  `aria-live="polite"`；`#toast` 加 `aria-live="polite"`；
- [ ] Step 2：`:focus-visible` 可见焦点环；
- [ ] Step 3：E2E 断言关键控件有可访问名（`getByRole`）；`test:all`。

**验收**：主要交互元素有可访问名；动态消息/提示可被读屏播报。

#### Task D1.3：对比度与动效（建议 v0.4.2）
- [ ] Step 1：核对正文/次要文字对比度（目标 WCAG AA ≥ 4.5:1），必要时加深/提亮 `--ink`/`--ink-mute`；
- [ ] Step 2：`@media (prefers-reduced-motion: reduce)` 关闭过渡/动效；
- [ ] Step 3：`test:all` → 提交。

**验收**：正文对比度达标；开启减弱动效时动画降级。

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| 工作目录被平台清空 | 每轮先确认 `game1` 存在，缺则 `git clone`；再 `reset --hard origin/main` |
| 推送 token 失效 | 用有效 PAT；失效即请用户重给 |
| E2E「角色头像」偶发 flaky | 单跑/复跑确认；必要时加重试 |
| 无障碍改动触碰既有 E2E | 键盘/ARIA 为**增量**，不改既有选择器；每步 `test:all` |
| 部署 DNS 劫持/无 key | 脚本已直连真实 IP；key 由用户提供 |
