### 发现的 P0 缺陷：一个请求即可杀死整个账号服务（已修复）

**复现**（修复前实测）：

```bash
curl http://127.0.0.1:8099/%
# → decodeURIComponent('%') 抛 URIError
# → 异常穿透 http 回调成为 uncaughtException
# → Node 进程直接退出，服务全挂
```

服务进程死亡后所有用户的登录态全部不可用，属于**远程拒绝服务**漏洞。
Instabox 线上实测不崩是因为 Instabox 网关在请求到达 Node 之前就拦截/规范化了
畸形 URL——**但这不是代码安全的依据**：部署到不经网关的环境
（自有服务器直连、`NH_HOST=0.0.0.0` 本机暴露）就会原样暴露。

**修复**（v0.9.10）：

1. `server/index.mjs`：解码包 `try/catch`，失败返回 400；
2. `server/index.mjs`：加 `uncaughtException` / `unhandledRejection` 兜底
   （只记录不退出，作为最后一道防线）；
3. `server/api.mjs`：设备会话 ID 解码同样保护，失败按 400 语义处理；
4. `server/test_api.mjs`：新增 3 条回归用例
   （`/%` 返回 400、半截编码不 5xx、畸形请求后服务仍存活）。

**教训**：Node 的 http 回调里任何同步异常都会变成 uncaughtException 杀死进程。
凡是对请求路径做 `decodeURIComponent` / `new URL` 之外的处理，都必须包 try/catch。
