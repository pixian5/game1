## 3. 结构性问题（有数据支撑）

### 3.1 内容节奏断点（最优先）

- **day5 零事件、day4 仅 1 条**：玩家在第 5 天只能靠出行/「等到明天」推进，缺少可玩的叙事节点。
- 路线链虽然覆盖部分时间，但属于「被动收消息」，缺少当日主动事件。
- 每天事件密度方差大（day10/16/18/20 仅 2 条），后半程容易变成「等消息」。

### 3.2 路线内容不均衡

- 消息数：陆辞 73 > 江屿 55 > 沈砚之 54 > 苏苏 66（系统向）。
- 三条男主线差异事件未形成独立节奏，J2「路线差异化」尚未落地。
- 独行线 17 个专属事件，主要集中在中后段，前期与男主线差异不明显。

### 3.3 架构耦合

- 61 个脚本按 `index.html` 顺序加载，全部挂在全局作用域（`window.STORY`、`engine`、`ui` 全局函数）。
- `story/01_events.js` 单文件 2226 行，事件定位与合并冲突成本高。
- 新增 UI 直接拼 `innerHTML`，转义依赖人工记得调用。

### 3.4 事件调度竞争

- 时间触发事件与 `then` 链共用同一延迟队列；历史出现「大步推进时间导致路线链滞后」「test_story 5 项失败」。
- 当前靠「时间推进前先派发 pending」缓解，但没有优先级模型。

### 3.5 存档与转义防御不足

- `endingGallery`、`todayFortune`、`pendingInteractions` 缺键白名单/长度上限。
- UI 中 `avatar src`、`style`、塔罗/节日字段未统一转义（数据当前可信，但缺防御纵深）。

### 3.6 测试短板

- `engine_save.js` 68%、`engine_progress.js` 70.5%，是主要未覆盖区。
- 三浏览器依赖系统图形库，本机与部分容器无法跑全量。
- 缺存档 fuzz（畸形 JSON）与「每天事件数」断言。

### 3.7 体验细节

- 长跑 120s 未读可堆到 12 条，缺「一键已读/分组折叠」。
- 空窗期引导已有「等到明天」，但缺少「今日小结 / 明日预告」。
- 无障碍：主要控件有可访问名，但键盘全流程与对比度未系统验证。

## 4. 下一步开发建议

> 按依赖排序，不含时间估算。每项给出文件、做法与验收标准。

### P0-A 补齐 day4–day5 内容（内容节奏）

- **文件**：`story/01_events.js`（建议新建 `story/01b_day45.js` 并加入 `test_helper.js` 的 `SOURCE_FILES`）
- **做法**：
  - day4 增 3 条、day5 增 3–4 条时间事件（`trigger:{day:4|5, hour:...}`），三线各 1 条 + 通用 1 条。
  - 每条带 `choice`（2 选项）、好感/性格 effects、`then` 链；避免与路线链同一小时触发。
  - 同步 `i18n/story-en-translations-*.js`。
- **验收**：
  - `npm run validate:story` 0 错误；
  - 新增断言：day4 ≥ 4、day5 ≥ 3（在 `validate_story.js` 增加「每日事件数」检查）；
  - `npm run test:story` 294/294；
  - 真实节奏通关 day4–5 至少收到 4 条新消息。

### P0-B 路线差异化（J2）

- **文件**：`story/01_events.js`、`story/14_critical_daily.js`
- **做法**：
  - 每条线在 day8–14 增 5–6 条专属事件（沈砚之/江屿补齐，陆辞保持），使用 `route` 条件隔离。
  - 每条专属事件绑定该线独有信物/地点（如沈砚之档案室、江屿排练室）。
  - 增加「线内连续剧情」：同一角色连续 2–3 天有推进，而非零散日常。
- **验收**：
  - 统计脚本输出：各线专属事件 ≥ 8；
  - 三次通关（shenyan/luci/jiangyu）触发事件交集 < 30%；
  - 双语 100%，validate 0。

### P0-C 存档健壮性收口

- **文件**：`engine_save.js`
- **做法**：
  - `endingGallery`：仅允许 17 个结局 id；
  - `todayFortune`：仅允许 `hint`/`level` 等白名单键，长度上限；
  - `pendingInteractions`：上限 50，元素 schema 校验；
  - `importSave`：非字符串输入同样做体积与结构校验。
- **验收**：
  - 新增回归 ≥ 4 例（超长队列、伪造 gallery、异常 fortune、非字符串导入）；
  - 恶意存档 E2E 仍通过。

### P0-D 统一转义入口

- **文件**：`ui/00_shell.js`、`ui/13_tarot_achievements.js`、`ui/15_holiday_perspective.js`、`ui/20_saves.js`
- **做法**：`avatar`、`style`、塔罗牌名、节日字段全部走 `escapeHtml`；新增一个 `safeAttr()` 处理属性值。
- **验收**：
  - 新增 lint 规则或 `check_ui.js` 检查：`innerHTML` 中出现 `${` 变量必须包裹 `escapeHtml`/`safeAttr`（白名单除外）；
  - 安全脚本三类注入仍通过。

### P1-A 拆分 01_events.js

- **做法**：按「序章/day 分段/路线/结局」拆为 4–6 个文件，保留 `STORY.events` 合并；更新 `test_helper.js`、`check_ui.js` 的脚本清单与 `sw.js` 预缓存（构建后自动对齐）。
- **验收**：拆分后 `validate`/`test_story`/E2E 全绿；单文件 ≤ 800 行。

### P1-B 事件调度优先级

- **文件**：`engine.js`、`interaction_queue.js`
- **做法**：给事件加 `priority`（route/critical > daily > ambient），`_queueEventDispatch` 与 `advanceTime` 按优先级出队；时间推进前 flush 改为「优先级 flush」。
- **验收**：新增回归：在 240 分钟大步推进下，路线链仍先于 day7+ 日常执行；`test_story` 全绿。

### P1-C 覆盖率与测试门禁

- **做法**：
  - `engine_save.js` / `engine_progress.js` 补直接测试（畸形存档、迁移、周目继承、自动动态）；
  - 目标覆盖率 75%；
  - 增加存档 fuzz（1000 条随机畸形 JSON，断言不崩溃、不注入）。
- **验收**：`npm run test:cov` 全文件 ≥ 75%；fuzz 用例通过。

### P1-D 三浏览器可运行化

## 6. 风险与依赖

1. **事件链耦合**：新增 day4–5 事件若与路线链同小时触发，可能重现队列竞争；必须先做 P1-B 或严格错开小时。
2. **双语同步**：每条新事件都要同步英译，否则商业测试 G 维度回落。
3. **拆分文件**：`build_bundle.mjs` 与 `sw.js` 预缓存需同步，`check_ui` 会拦截遗漏。
4. **浏览器依赖**：三浏览器验证依赖系统库，容器环境需预装。
5. **存档兼容**：新增字段需在 `save_migrations` 注册，避免旧档读入失败。
