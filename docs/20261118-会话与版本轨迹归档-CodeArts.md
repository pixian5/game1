## 3. 关键失败与最终方案（务必保留）

### 3.1 第一次失败：day6–7 直接接入 → test_story 5 项失败

- 现象：开幕式选项 / 雨夜回程 / 半个月后 / 觉醒选项 / 结局触发 全部超时。
- 原因：新增事件与主线链在同一会话叠加；测试驱动按「任意 choice」匹配，误消费新增事件的选择，主线 `then` 链断裂。
- 已尝试但无效：
  1. 有 `pendingChoice` 时延后派发（判定过窄）
  2. 日常选择自动结算（时序仍错）
  3. 测试优先消费历史选择（只是把问题后移）
- 处理：撤回 day6–7 与引擎时序改动，保留 v0.9.3 基线。

### 3.2 第二次失败：隔离范围过宽

- 现象：`test:regressions` 中「首个雨天剧情」失败。
- 原因：忙碌判定对所有时间事件生效，既有雨天事件被延后。
- 处理：隔离只对带 `deferWhenBusy` 的新事件生效。

### 3.3 最终方案（v0.9.5，已验证）

1. `_mainChainBusy()`：`pendingEventDispatches` / `pendingMessages` / `pendingInteractions` / 会话与群聊 `pendingChoice` 任一存在即为忙碌。
2. 带 `deferWhenBusy` 的事件忙碌时进入 `deferredEventIds`，空闲后补派；超过 15s 强制派发（防死锁）。
3. 新增事件选项 `choice.auto = true`：投递时自动结算首选项（好感/性格/后续回复），不弹选择、不占会话。
4. 结果：63/63、294/294；day6 档案 / day9 预展 / day11 评论家均实测触发，`pendingChoice=false`，路线隔离正确。

## 6. 环境教训

- 工作区多次被外部回滚（文件消失、HEAD 退回旧提交）：`git fetch … && git reset --hard FETCH_HEAD` 即可恢复。
- 工具前台长任务（sleep >30s、长时间 node）会挂起：用 `setsid nohup … &` + 短轮询。
- `node_modules` 权限会丢失：`chmod +x node_modules/eslint/bin/eslint.js node_modules/@playwright/test/cli.js`。
- Playwright 自带 Chromium 路径随版本变化：脚本统一用 `tools/browser.mjs` 的 `launchBrowser()`，`PW_CHANNEL=none` 走自带内核。
