## 1. 测试目标

1. 验证「新玩家从锁屏到结局」的完整闭环可走通，且 4 条路线、17 个结局均可到达。
2. 验证手机模拟外壳、30+ App、消息并发/已读不回、电话、群聊、约会、收集、周目等核心玩法无阻断缺陷。
3. 验证发布态 `dist/` 与开发态行为一致，三个公网入口、PWA 离线、中英双语可用。
4. 建立可重复的自动化回归集，把现有 57 项回归、294 项剧情断言、16 项 E2E 纳入发布门禁。
5. 输出可定位、可复现的缺陷证据（截图、console、NeonDebug 日志、存档 JSON、复现步骤）。

**不测范围**：付费/账号体系（无）、服务端接口（无后端）、第三方平台内部实现（GitHub Pages / HF Space 托管行为仅验证可达性）。

| `tools/endings.mjs` | 17 结局批量验证 | 每条线按 §6 构造 flag，走真实结局事件，断言图鉴 17/17 |
| `playwright/full-flow.spec.js` | 冒烟闭环 | 序章 → 路线 → 结局屏，断言论标题与 console=0 |
| `tools/report.mjs` | 汇总 | 合并 console/pageerror/requestfailed/NeonDebug/截图索引为 JSON + HTML |

### 7.3 自动玩家稳定性规则（重要）

1. **禁止无条件快进**；只有 `firedEvents`、消息数、天数连续 1.5s 无变化时才推进 15 分钟。
2. 处理顺序固定：结局 → 路线弹窗 → 来电 → 通话选项 → 梦境 → 梦魇 → 偶遇 → 约会 → 闪回 → 旁白选项 → 消息选项 → 群聊选项 → 空闲推进。
3. 点击消息选项前校验 `currentConvId === pending.cid` 且 `#chat-input-bar` 可见，避免点到隐藏的旧选项（对应 R3）。
4. 每步失败写诊断：`firedEvents` 尾部、`pendingInteractions`、`pendingEventDispatches`、定时器数、当前屏。
5. 单次运行设硬超时，超时输出当前状态与截图，不静默挂起。

### 7.4 断言与证据

每个用例至少产出：**结果**（pass/fail/blocked）、**截图**（关键屏）、**console 错误**、**NeonDebug issues**、**复现存档**（必要时导出 JSON）。
