# 霓虹心事 · v0.8.1 限时回复与会话计时修复

> 依据：v0.8.0 代码审查报告（P2-1 / P2-2 / P3-2 / P3-3 / P3-1）
> 版本：0.8.0 → 0.8.1
> 执行：CodeArts · 2026-11-06

## 1. 修复内容

### 1.1 限时回复不再被切会话重置（P2-1）

- 引擎在投递带 `timeout` 的选项时写入绝对截止时间 `choice.dueAt = Date.now() + timeout * 1000`，并克隆选项对象，避免污染 `STORY` 源数据。
- `showChatChoice` 只使用已有 `dueAt`，不再按 `choice.timeout` 重新计时；重新打开会话只重建视图。
- 若打开时已过期，直接按默认项结算，避免“过期后仍显示选项”。

### 1.2 计时器按会话管理（P2-2）

- `ui/00_shell.js` 新增 `chatTimeouts: Map<convId, {handle, dueAt, totalMs, onTimeout}>`。
- `startTimeout(convId, dueAt, totalMs, onTimeout)` 按会话注册与清理；点击选项、自由输入、读档/重置 UI 都会清理对应计时器。
- 多个会话同时限时时不再互相覆盖。

### 1.3 存档保留限时与自由输入字段（P3-3）

`engine_save.js` 的 `sanitizeChoice` 现在保留 `timeout`、`dueAt` 与 `freeInput`（placeholder、keywords、defaultEffect），并继续做长度与事件白名单校验。读档后倒计时按真实剩余时间继续。

### 1.4 旁白选择空值防御（P3-2）

`showNarratorChoice` 入口校验 `choice/options`，异常数据不再抛 `reading 'prompt'`。

### 1.5 错误上报仅限自有服务器（P3-1）

`pwa.js` 仅在 `oh.sbbz.tech` 或 9443 端口启用 `/collect-error`，HF Space、GitHub Pages、本地不再产生 404。

## 2. 新增回归用例

`playwright/timeout-reset.spec.js`：

1. 注入 8 秒限时选项，打开会话读取剩余秒数。
2. 切到另一会话 1.6s 后再切回。
3. 断言剩余秒数**小于**首次读取值（未被重置）。
4. 等待超时后断言 `pendingChoice` 已被清空（自动结算生效）。
