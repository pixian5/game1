## 二、缺陷 1（P0）：选择被覆盖导致主线静默中断

### 现象

加速跑测（`playthrough.mjs`，仅压缩 ≤3s 的定时器）下：

- 主线推进到 day3「陆辞关心」后彻底停住；
- `luci_care_msg_2` 已触发，但 `luci_care_reply_1` / `dream_day3_evt` / `opening_day` / `route_choice_trigger` 全部未触发；
- 游戏继续推进到 day21，随手拿到大量日常事件，但**永远进不了路线**。

### 根因

`engine.js` 中每个会话只有**一个** `pendingChoice` 槽位：

```js
// 旧实现（engine.js _deliverPendingMessage）
if(msg.choice){
  conv.pendingChoice = msg.choice;   // 直接覆盖，不检查是否已有未答选择
  this.emit('choicePrompt', {...});
}
```

当同一会话里两条带选择的消息先后到达（例如 day3 的「陆辞关心」和「陆辞约饭」），
后一条会**静默覆盖**前一条。被覆盖的选择对应的 `thenEvent` 永远不会派发，
而主线恰好在「陆辞关心」的选项里：

```
luci_care_msg_2 → (选项) → luci_care_reply_1 → dream_day3_evt → opening_day → ... → route_choice_trigger
```

覆盖一旦发生，这条链就断了；游戏仍能继续跑日常，所以**看起来像“玩到后面没剧情”**，很难被发现。

### 复现（最小）

```js
engine.scheduleEvent('luci_care_msg_2');   // 挂起「陆辞关心」
engine.scheduleEvent('luci_reunion_msg_4'); // 挂起「陆辞约饭」，覆盖前一条
// 旧行为：luci_care_reply_1 永不派发
```

### 修复

保留「一个会话只显示一个选择」的既有 UI 语义，但在覆盖发生时**按默认项结算被顶掉的选择**，
并显式派发其 `thenEvent`（`_applyEffects` 不处理 thenEvent，必须单独派发）：

```js
_setPendingChoice(target, choice){
  const superseded = target.pendingChoice || null;
  target.pendingChoice = choice;
  if(superseded) this._settleSupersededChoice(superseded);
  return superseded;
}
```

同时新增 `choiceSuperseded` 事件，便于观测与测试。

**设计取舍**：曾尝试「排队 + 答完提出下一条」，但会改变既有 UI 契约（`choicePrompt` 语义、
294 条剧情断言、读档恢复路径全部依赖“当前唯一选择”），改动面过大且容易引入新回归。
最终选择「覆盖即结算」——**最小改动、零 UI 契约变更、彻底消除断链**。

## 三、缺陷 2（P1）：路线选择弹窗挂载在 home-screen

### 现象

`ROUTE=jiangyu` 通关在路线选择处报错：

```
locator '#route-choice-modal [data-route="jiangyu"]' resolved to <button>
- element is not visible
- retrying click action … 56 ×
```

### 根因

```js
// 旧实现（ui/07_notes_logs_endings.js）
showScreen('home');
const home = $('home-screen');
...
home.appendChild(modal);
```

弹窗挂在 `#home-screen` 内。若玩家此刻停留在其它 App，或 `showScreen('home')` 被后续事件覆盖，
弹窗虽然创建成功，但 `offsetParent === null`，玩家看不到、自动化点不到。
这与 v0.7.6 修过的「旁白选择不可见」是**同一类问题**，但当时只修了旁白弹窗，漏了路线弹窗。

### 修复

1. 弹窗改挂 `#phone` 顶层（与旁白弹窗一致），并补 `role="dialog"` / `aria-modal="true"`；
2. 弹窗文案走 `t()`（顺带补上英文模式残留）；
3. **配套修复**：`restorePendingUi()` 在锁屏期间直接返回 `false`，
   解锁时（新增 `unlock()`）再调用一次——否则读档时弹窗会盖住锁屏，玩家无法解锁。

## 七、经验

1. **「能跑完」和「跑对了」是两件事**。基线全绿（65+294+21）却完全无法通关——
   因为所有自动化测试都在验证「单点行为」，没有验证「主线能不能走到结局」。
   `playthrough.mjs` 这类端到端脚本必须作为常规门禁，而不是一次性工具。
2. **同一会话多选择并存是真实场景**，不是边界情况：day7-14 每条线都有密集日常，
   与主线选择并发是常态。单槽位模型必须有覆盖仲裁策略，否则任何并发都会静默丢剧情。
3. **修复要选「契约兼容」的形态**。排队方案更“正确”，但会冲击 294 条断言与 UI 语义；
   覆盖即结算同样消除断链，且改动仅 20 行、零契约变更——这才是这个代码库该选的解法。
4. **同类缺陷要一次性扫干净**。v0.7.6 修了旁白弹窗的挂载位置，但没扫路线弹窗；
   本轮把两个弹窗都收口到 `#phone`，并顺带补了 `role/aria-modal`。
