## 3. 关键问题诊断

### 3.1 P0：主线调度仍不是确定性的

**链路**：`photo_rooftop` → `route_choice_night`（`advance_day` 到 23:00）→ `route_choice_msgs`
（`message_batch`，delay 1）→ `route_choice_trigger`（`route_choice`）。

**机制**：

- `_queueEventDispatch` 用真实 `setTimeout`（400ms / 2.8s），不是虚拟时钟；
- `advanceTime` 只做 `_flushPendingEventDispatches`，队列是 **FIFO**，没有「主线优先」；
- `checkTimeEvents` 会把当前 day/hour 命中的所有事件一次性 `scheduleEvent`，日常事件可与主线链交错；
- 路线选择前没有 `routePending` 窗口锁，`soloOnly` 日常（如 `week1_review`）可能先弹出 choice。

**证据**：`docs/20261031-2200-v0.7.5-测试执行报告-CodeArts.md` P2-1；
`docs/20261031-2230-v0.7.6-测试修复与复验-CodeArts.md` §4「P2 未完全消除」。
加速跑测下路线选择可被推到 day10+，男主线剩余天数被压缩。

**影响**：这是核心流程正确性问题，不只是测试问题。真实玩家按正常节奏大概率 day4 触发，
但一旦玩家手动快速推进时间、或设备卡顿/后台切换，就可能错序。

**建议**：不要重写调度器；先加「优先级 + 窗口锁」：

1. `_queueEventDispatch` 增加 `priority`（`critical` > `mainline` > `daily`），`_flushPendingEventDispatches` 按 `(dueAt, priority)` 排序；
2. `route_choice_night` 派发时置 `state.flags._routePending = true`，`chooseRoute` 后清除；`checkTimeEvents` 在此期间跳过 `soloOnly` 日常；
3. 路线选择弹窗出现时，阻塞其他 choice 交互（复用 `pendingInteractions` 的队列优先级）；
4. 增加「day4 路线选择」断言与 4 条路线全通测试（真实时钟 + 10 倍 + 100 倍三档）。

### 3.2 P1：男主线内容纵深不足

| 内容 | 独行线 | 三条男主线 |
|---|---|---|
| 专属日常（`soloOnly`） | **17 条**（day7-21） | 0（进线后全部跳过） |
| 共享日常（`inRoute`） | 0 | **7 条**（day15-21，三条线共用同一份） |
| 路线链事件 | 真结局链 | 沈砚之 17 / 陆辞 17 / 江屿 18 |
| 临界事件 | 无 | 每条线 6 条（stage 3 一次邀约） |
| 二周目中段变体 | 真结局尾声 1 | 每条线 2 个 |

**问题**：选线后 day7-14 没有角色专属的「日常感」内容，路线链又用 `advance_day`（「半个月后」「南方出差」）
做时间压缩，导致男主线更像「一条短链」而不是「21 天的手机生活」。这削弱了本作最大的差异点
（手机日常的陪伴感），也让三条线在体感上趋同。

**建议**：新增 `trigger.route`（按角色区分，而不是现在的 `inRoute` 只判断「是否男主线」），
为每条男主线补 day7-14 的 3 条专属日常；共享 7 条 `inRoute` 事件可用 `flavors` 做角色语气变体，
避免三倍复制。

### 3.5 P1：三端发布产物不一致

| 平台 | 产物 | 首载 |
|---|---|---|
| 自有服务器 | `dist/`（单 bundle） | 快 |
| HF Space | `dist/`（单 bundle） | 快 |
| **GitHub Pages** | **仓库源码（61 脚本）** | **慢（历史上 18s）** |

同时：

- `deploy-server.yml` 与 `deploy-hf.yml` 各自 `npm ci` + 重复校验；`deploy.yml` 不构建；
- 三条工作流各自触发，缺少「构建一次、三端复用」的 reusable workflow；
- 没有部署后自动校验：三端版本、bundle 哈希、关键资源是否 200；
- 自有服务器 2026-10-28 出现过整机级故障（sshd/nginx 全部失效，只剩 ICMP），现已加 systemd timer 告警，
  但仓库侧没有外部 uptime/版本漂移检查；
- HF Space 的 OG 图仍是相对路径，社交分享无预览；`HF_TOKEN` 目前是写权限长期 Token。

**建议**：

1. 抽 `build.yml`（reusable workflow）：`npm ci` → 全量校验 → `build_bundle` → 上传 artifact；
2. 三端部署只消费 artifact：Pages 发 `dist/`，服务器 rsync `dist/`，HF 上传 `dist/`；
3. 新增 `tools/verify_deploy.mjs`：curl 三端，解析 `<meta name="version">` 与 `bundle.js` 哈希，
   与 `VERSION` 比对；部署后跑一次 + 每日 cron；
4. nginx 落 `Content-Security-Policy`（含 `frame-ancestors 'none'`）、`X-Frame-Options: DENY`、
   `Referrer-Policy`、`Permissions-Policy`；meta CSP 只作兜底；
5. HF：OG `og:image` 改绝对地址；Token 改细粒度（仅该 Space 写权限）；自定义域名可选。

- 部分历史文档记录过 PAT 前缀（`xRF8cXTx…`），若该 Token 仍有效，建议轮换/吊销并清理文档；
- 存档导入已有白名单与长度上限（v0.4.4/v0.1.0），这块做得不错。

**性能**：

- `bundle.js` 685KB、`assets` 2.75MB；没有运行时性能门禁（只有静态体积预算）；
- 仅一个 480px 断点；平板/桌面缩放、iOS 安全区、`100vh` 键盘遮挡未系统验证；

**无障碍**：

- 键盘可玩、`#toast`/消息 log 的 `aria-live`、主要控件可访问名已完成；
- 但动态弹窗（`narrator-choice-modal`、`route-choice-modal`）没有 `role="dialog"` / `aria-modal` /
  `aria-labelledby`，没有焦点陷阱与 Esc 关闭；`ui/` 中仅语音信箱有 4 处 `aria-*`；
- 没有 axe 自动审计，也没有读屏走查记录。

**建议**：把无障碍作为 H3 的一部分：先补弹窗语义与焦点管理，再上 axe 门禁；
性能先做「Lighthouse + WebP」两项，不追求过度优化。

**全 STORY 覆盖率统计口径**（本文新增，供后续工具化）：

- 递归遍历 `STORY`，收集 `text / prompt / desc / onSuccess / onFail / title / caption / meaning / how / name / label / note / summary`

- 该口径包含专有名词（地点/牌名/结局名），若只算句子级文案比例会更高，但**缺口面一致**，足以说明英文模式不完整。
