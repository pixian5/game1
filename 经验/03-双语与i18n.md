# 03 · 双语与 i18n

> 来源：v0.7.4 角色名英文化、v0.8.8 双语长尾收口、v0.9.12 英文模式补全与残留实测（2026-11-24 至 11-25 实测，本篇以此为准）
> 操作细节见 `docs/20261125-2335-v0.9.12-英文模式补全与残留实测工具-GLM-5.4.md`。

## 一、最重要的一条：字典覆盖率不等于界面全英文

历史上多次出现「字典 100%，界面还有中文」：

- v0.9.4 的「双语 100% 收口」只是字典覆盖率；
- 2026-11-24 首次在浏览器里实测：英文模式下 **31 个应用里 20 个显示中文**；
- 首层清零后，点进详情页、弹层还有 48 种；
- 直接扫源码才看到全貌：界面代码里 241 条整条文字 + 29 种拼接没有英文。

所以评价双语至少要看三个数：**字典覆盖率、界面代码字面量覆盖率、浏览器里实测的残留数**。只报第一个数没有意义。

## 二、语言包结构

```
i18n/zh-CN.js                         中文运行时文案
i18n/en-US.js                         英文界面文案（固定文字、按钮、提示、拼接模板）
i18n/story-en-translations.js         剧情与数据文案英译（第 1 批）
i18n/story-en-translations-2..12.js   第 2 至 12 批
i18n/index.js                         查找、切换、拼接文字自动套用
```

所有译包都合并进同一个字典 `window.I18N_PACKS['en-US']`，分文件只是为了好维护；
所以「放在哪个文件」不影响是否生效，**有没有生效取决于首页有没有引用**。

**新增译包要做三件事**：在 `index.html` 加 `<script>` 标签（放在上一包之后）、在 `sw.js` 的预缓存清单加一行、跑 `npm run test:i18n`
（里面有「目录里有译包但首页没引用」的检查）。第 9 号译包曾经「文件在线上、首页没引用」，白白躺了好几天没人发现。

## 三、四层机制（各管一段）

| 层 | 做什么 | 典型写法 |
|---|---|---|
| 显式翻译 | 数据里的文字在渲染处翻译 | `optText(opt)`、`tEsc(s)`、`tBr(s)`、`window.t(s, vars)`（都在 `ui/00_shell.js`） |
| 整条兜底 | 界面每次变动后，把「与字典键完全相同」的整段中文换成英文 | 不用写代码，自动生效（`ui/00_shell.js` 的显示层兜底） |
| 拼接自动套用 | 文字是拼出来的（「第13天的牌阵 · 逆位」），按字典模板的形状套用 | 字典里写模板：`"第{n}天的牌阵 · {r}": "Day {n} draw · {r}"` |
| 静态文字 | 首页里写死的文字 | `data-i18n="中文原文"` 等属性 |

**新代码仍然应该显式翻译**。后两层是安全网，不是偷懒的理由：安全网只处理「整条文字」，拼法一变就可能对不上。

## 四、拼接文字怎么写

翻译函数只认「整条文字完全相等」。只要拼了数字、名字、天数，就对不上字典。三种情况：

1. **渲染处知道各部分是什么**（最推荐）：显式调用带占位符的模板。
   ```js
   window.t('第{n}天的牌阵 · {r}', {n: fortune.day, r: window.t(fortune.reversed ? '逆位' : '正位')})
   ```
   变量里的中文（人名、道具名、策略名）要自己先过一遍 `window.t`。
2. **字符串拼接（加号）**：显示层完全看不到，必须改成显式调用。例如 `'已收集 ' + n + ' 个记忆碎片'`。
3. **模板字符串里直接写中文加变量**：显示层会按形状自动套用，前提是字典里有对应模板。

字典里的模板键写成「显示出来的样子」：`"策略：{name}"`、`"📱 新 App 上线：{name}"`。
占位符的名字可以随便取，比对的是形状；占位符两侧有没有空格也不影响。

**模板自动套用的四条保护**（`i18n/index.js` 的 `translateAuto`）：

- 只在非中文模式下工作；
- 字面量不足 2 个字的模板不参与（`"{n}天"` 这种太短，玩家输入「明天」会被误套）；
- 占位符里截到的中文必须自己查得到译文，否则放弃这次匹配——
  **套错比不翻更糟**：「✦ 新收集：X」曾被套成「✦ Easter egg: X」；
- 空白按显示效果比对（换行、缩进、连续空格算一个空格）。

## 五、显示层兜底的范围

- 观察**整个页面**，不只是手机容器：解锁横幅、礼物弹层、闲逛提示等都直接挂在页面根上。
  曾经有十来处横幅完全不在检查范围里。
- 文字节点、图片替代文字、悬停提示、输入框占位提示、无障碍标签、提示浮层、通知、浏览器标签页标题。
- **不碰**输入框、可编辑区域、标了 `data-i18n-skip` 的元素：玩家自己输入的内容不能被改。
- 只改显示，不改数据：存档与发给引擎的仍是中文原文（存档与显示层分离的既有约定）。

## 六、三道检查（新增或修改界面文字后都要跑）

| 命令 | 看什么 | 在哪里跑 | 在总闸的哪一档 |
|---|---|---|---|
| `npm run check:i18n-literals` | 扫源码里全部中文字符串与拼接，逐条对照字典 | 本机，不用浏览器 | 推送前钩子 |
| `npm run check:i18n-choices` | 剧情里的选项、提示语、问卷题目是否都有英文 | 本机，不用浏览器 | 推送前钩子 |
| `npm run test:i18n` | 字典完整性、自动套用的各条保护、中文模式不改写 | 本机，不用浏览器 | 推送前钩子 |
| `npm run check:i18n-leak` | 浏览器里打开全部应用的首层界面，数还剩多少中文 | 本机，需要本地服务器 | 默认档 |
| `npm run check:i18n-leak:deep` | 再逐类点进详情页与弹层（约 2 分钟） | 本机 | 完整档 |
| `BASE=<线上地址> npm run check:i18n-leak` | 线上模式：没有调试入口，只查已解锁的应用 | 本机 | 手动 |

**字面量覆盖检查**（`tools/i18n-literal-coverage.mjs`）的要点：

- 模板里的 `${表达式}` 归一成占位符后比对形状；表达式本身是 `window.t('固定文字')` 时代入固定文字再比对。
  只比对形状会出漏洞：「✦ ${t('新收集')}：${…}」曾被看成「✦ {}：{}」，与「✦ 彩蛋：{name}」形状相同而被判为已覆盖。
- 确认不是给玩家看的文字，写进 `tools/i18n-literal-allow.txt`，每条带原因（例如只在中文模式下才拼接、成就说明的隐藏标记）。
  不要为了让检查通过而随手加例外。

**残留扫描**（`tools/i18n-leak-scan.mjs`）会自证结果可信，这三样都是踩坑后加的：

- 对照自检：扫描前故意放两条中文到页面上，结束时必须都被抓到；
- 等待函数必须真的等待，否则直接抛错；
- 没打开任何应用、没看到界面文字、页面有异常、自检失败，一律退出码 2「扫描自身异常」，不会报成零残留。

退出码：0 没有残留；1 有残留；2 扫描自身异常（结果不可信）。

## 七、新增文案的标准流程

1. 先在代码里写中文；
2. 加英文：界面文案进 `i18n/en-US.js`，剧情与数据文案进 `story-en-translations-*.js`；
3. 跑 `npm run check:i18n-literals` 与 `npm run check:i18n-choices`，缺什么补什么；
4. 跑 `npm run check:i18n-leak`（改了详情页或弹层再加 `:deep`）；
5. 确认框（`confirm`、`alert`）里的文字不在页面上，显示层兜底管不到，必须显式翻译。

新增任何带文字的剧情或界面，都必须同一次提交里补上英译，不要留到「下一轮再补」——历史证明这样一定会积压。

## 八、另外几条约定

- **译名用拼音**：用户明确决定，人名等专有名词用拼音转写，不用意译。
- **模板字符串里必须用真正的插值**：`` `<div>${window.t('某key')}</div>` ``。
  写成 `` `<div>' + window.t('某key') + '</div>` `` 会原样输出那串字符，本项目踩过多次；排查时搜索 `' + window.t(`。
- **想输出字面量 `${` 要写成 `\${`**，否则会被当成插值。
- **切换语言要重渲染**：只换字典不重绘，屏幕上已有的文字仍是旧语言。切换时会派发 `i18nchange` 事件，显示层兜底也会整体再兜一遍。
- **日期是「中文快照 + 显示层重拼」**：备忘录、朋友圈、存档摘要里存的是「7月15日 星期二」这样的中文，
  显示时用 `window.localizeDateLabel()` 重拼。开局 2025 年 7 月 15 日实际是**星期二**（曾误写成星期三）。
- **主角姓名长度按语言区分**：`engine.playerNameMaxLength()`，中文 6 个字、其他语言 12 个字符。界面输入与读档清洗共用，不要各写一个数字。
- **字典里的模板译文，占位符名字必须与中文键一致**：键用 `{n}`、译文写成 `{m}` 的话，界面会原样显示「{m}」。`npm run test:i18n` 有检查。
- **往字典里写换行**：文件里要是一个反斜杠加 n（真正的换行）。曾经写成了两个字符，模板匹配不上。
- **发给引擎的选项文字保持中文**（存档与显示层分离），只在渲染时翻译。

## 九、还没有覆盖到的地方

- 剧情中后期才出现的界面（电话通话中、约会场景、偶遇、结局画面、旁白选择弹窗）没有纳入残留实测。
  这些界面的文字已由字面量覆盖检查保证「字典里有译文」，但「界面上是否真的用上」没有实测。
- 应用图标名称（`manifest.json`）与链接预览信息（开放图谱协议元标签）仍是中文。
- 玩家自己输入的文字在英文模式下保持原样，这是设计如此。
- 线上模式只能查新开局已解锁的 9 个应用；完整的 31 个应用是在本机对同一份构建产物测的（代码包哈希与线上一致）。

## 十、历史教训（已被 v0.9.12 修复，留作提醒）

- v0.9.11 及之前有 10 处选项渲染直接写 `escapeHtml(opt.text)`，没有调用翻译函数，
  所以英文模式下选项按钮全是中文。现已统一改用 `optText(opt)`、`tEsc(s)`。
- 原有的「翻译缺口」检查（`tools/i18n-gap.mjs`）只查字典里有没有某个键，不查界面会不会用，所以一直报 0 条缺口。
- 写扫描工具时的一个错误：等待函数写成了「不等待」，在界面还没渲染完时就取文字，报出一堆假残留，
  而点击次数、可见文字数这些统计数字看着都合理。**任何「零残留」的结论，先确认工具真的看到了东西。**
