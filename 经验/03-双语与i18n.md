# 03 · 双语与 i18n

> 来源：v0.7.4 角色名英文化、v0.8.8 双语长尾收口、v0.9.4 双语 100% 收口、i18n-gap 工具实现

## 一、语言包结构

```
i18n/zh-CN.js                    中文运行时文案
i18n/en-US.js                    英文运行时文案
i18n/story-en-translations.js    剧情文案英译（第 1 批）
i18n/story-en-translations-2..8.js  剧情文案英译（第 2-8 批）
i18n/index.js                    加载与切换入口
```

**运行时文案**（界面上的固定文字、按钮、提示）放 `en-US.js`。
**剧情文案**（事件里的对话、旁白）放 `story-en-translations-*.js`。
放错地方的表现是：切到英文后那一条仍然是中文。

## 二、模板字符串陷阱（最容易犯的错）

在反引号 HTML 模板里插值，必须用真正的插值语法：

```js
// 正确
el.innerHTML = `<div>${window.t('某个key')}</div>`;

// 错误：这样写会原样输出字符串 "window.t('某个key')"
el.innerHTML = `<div>' + window.t('某个key') + '</div>`;
```

第二种写法是把普通字符串拼接的写法搬进了模板字符串里，
在模板字符串内它就是纯文本，不会执行。**这个问题在本项目里被踩过多次**，
排查方式是搜索 `' + window.t(` 这种模式。

另一个反向陷阱：想输出字面量 `${` 时要写成 `\${`，否则会被当成插值。

## 三、译名用拼音

用户明确决定：人名等专有名词用**拼音转写**，不用意译。
这条决定了 `en-US.js` 里的角色名映射表。

## 四、新增文案的标准流程

1. 先在代码里写中文
2. 在 `i18n/zh-CN.js`（界面文案）或对应 story 译包（剧情文案）加中文条目
3. 在 `i18n/en-US.js` 或对应 story 译包加英文条目
4. 跑 `node tools/i18n-gap.mjs` 检查缺口
5. 用抽取器确认口径：`node tools/extract_story_strings.mjs`

**关键：抽取器的口径要和渲染面一致。**
历史上出现过"抽取器认为 100%、实际界面还有中文"的情况，
原因是渲染面用了拼接或变量，抽取器扫不到。
所以 `extract_story_strings.mjs` 后来补了 flavors（消息变体）和 unlockMsg（解锁提示）两个口径。

## 五、切换语言要重渲染

切语言不能只换字典，必须把当前界面全部重绘一遍。
早期只换了字典，结果已经在屏幕上的消息仍是旧语言，
必须退出再进入才变。

## 六、CJK 泄漏检测

有一个用例专门扫：切到英文后，界面上是否还出现中日韩字符。
覆盖 18 个 App，要求 0 泄漏。新增界面时必须加进这个用例，
否则新界面漏译不会被发现。

## 七、当前状态

- 双语覆盖率：**100%**（v0.9.4 收口）
- story 译包已扩到 **8 个文件**
- 已知残留：外设界面（商店描述、设置说明、日期状态标签）曾有约 12 条未译，
  v0.9.4 之后需用 `i18n-gap.mjs` 复核是否清零

## 八、每次内容提交的固定动作

```bash
node tools/i18n-gap.mjs
```

新增任何带文字的剧情/界面，都必须同一次提交里补上英译，
不要留到"下一轮再补" —— 历史证明这样一定会积压。
