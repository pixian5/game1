# 04 · 存档与安全

> 来源：v0.1.0 完整性修复、v0.1.2 存档恢复、v0.1.3 交互恢复、v0.1.4 交互队列、v0.9.4 存档加固

## 一、存档导入必须是白名单

**绝对不要**把导入的 JSON 直接合并进状态。正确做法是逐字段读取、校验、重建：

```js
// engine_save.js 里的 _sanitizeLoadedState
out.day = asInt(source.day, def.day, 1, 999);        // 有默认值 + 上下界
out.affection[char] = asInt(..., 0, 999);            // 上限 999，不是 9999
```

原则：
- 数值一律过 `asInt(value, default, min, max)`
- 数组要限制长度和元素类型
- 字符串要限制长度
- **未知字段一律丢弃**（v0.9.4 加了字段白名单）
- 重新生成摘要和时间，不相信存档里的值

**为什么重要**：恶意或畸形的存档能直接进入渲染层，
造成 XSS 或者把引擎状态搞坏（例如 `day: NaN` 会让所有时间事件失效）。

## 二、异步状态必须持久化

**这是本项目历史上最严重的一类 bug，修了三轮。**

只存 `firedEvents` 是不够的。以下状态如果不存，刷新后会永久丢失：

| 状态 | 丢失表现 | 修复版本 |
|---|---|---|
| 待送达的消息 | 开场消息再也不出现 | v0.1.2 |
| 链式事件的后续 | 剧情链断在半路 | v0.1.2 |
| 来电预约 | 电话永远不来 | v0.1.2 |
| 路线选择界面 | 读档后界面空白 | v0.1.3 |
| 旁白选择 | 同上 | v0.1.3 |
| 偶遇弹窗 | 同上 | v0.1.3 |
| 梦境/梦魇全屏界面 | 卡死或跳过 | v0.1.3 |

v0.1.4 的解法是把路线选择、旁白选择、偶遇、来电统一成
**`pendingInteractions` 队列**，可并发持久化，并做了 SaveMigrations v2→v3。

**判断标准**：任何"玩家正在看但还没操作完"的东西，都必须能存能恢复。

## 三、存档字段的边界值

- `day`: 1-999
- 好感（含三轴分项）: 0-999
- `MAX_SAVE_BYTES`: 1,500,000（超出拒绝）
- 槽位数: 4 个，外加导入导出 JSON

## 四、存档迁移

`SaveMigrations.migrate` 负责版本升级。
新增存档字段后的规矩：**旧存档必须能读进来**，缺失字段用默认值补齐，
不要写 `state.newField.xxx` 这种假设字段一定存在的代码。

## 五、XSS 防御

所有用户可影响的内容（昵称、群名、会话预览、通话记录、日历、记忆碎片）
渲染时必须转义。v0.4.4 专门补了一轮，并加了注入 E2E 用例。

**新增任何把变量拼进 innerHTML 的地方，都要问一句：这个变量玩家能不能控制？**

## 六、存档性能

`getAllSaves()` 用内存缓存 `_savesCache`，
不要每次都遍历 localStorage 反序列化 —— 存档列表界面会明显卡顿。

## 七、修改存档逻辑后的验证

```bash
npm run test:regressions    # 含存档相关用例
```
重点看这几条是否通过：
- "存档/日志仍存中文 name 快照（显示层才翻译）"
- "localizeDateLabel——中文快照显示层重拼"
- 存档导入导出的白名单用例

手工验证：导出一个旧版本存档，导入，确认不报错且关键进度还在。

## 八、账号系统：带登录态的 GET 绝不能进 Service Worker 缓存

v0.9.9 最严重的坑：`sw.js` 曾对所有同源 GET 走 cache-first，
`/api/auth/me` 的游客响应被缓存，登录后刷新仍拿到 `{user:null}`，表现为“随机掉登录”。

做法：
- `sw.js` 的 fetch 开头 `if(url.pathname.startsWith('/api/')) return;`
- `check_ui.js` 加源码守卫，防止以后又被人改回去
- E2E 在刷新前等 `navigator.serviceWorker.controller`，确保测的是真实 SW 生效场景

其它账号安全约定：
- 密码 scrypt 哈希 + 随机盐；会话 token 只存 SHA-256，Cookie HttpOnly+SameSite=Lax
- 非 GET 必带 `X-Requested-With`；有 Origin 时校验 host，防 CSRF
- 注销：先删该账号 audit_log，再删 users（sessions/saves 外键级联），避免残留可关联数据
- 导出应包含资料、云存档、设备会话、安全记录，才算法定的“完整导出”
