## 一、铁律：只发 dist

根目录有 68 个独立脚本，直接当站点根会串行请求，首屏 18.4 秒；
发 `dist/`（单 bundle）后约 3.5 秒。**任何平台都只发 dist。**

```bash
node tools/build_bundle.mjs
# 然后用 dist/ 的内容
```

## 三、自有服务器的历史坑

- **nginx 监听 9443**，因为 80/443 被服务器上既有的代理服务占用了，**不可触碰**
- **`add_header` 不继承**：在某个 `location` 里写了 `add_header`，
  父级的其他 `add_header` 会全部失效，必须在该层重写完整
- **`deploy.sh` 的清单必须与 index.html 的依赖一致**：
  早期漏了 `i18n/` 和 `privacy.html`，线上直接 404
- **`rsync --delete` 有风险**：源目录不全时会删掉线上文件
- 证书用 acme.sh 的 DNS-01 方式，自动续期

## 四、CDN 缓存滞后

GitHub Pages 改完 `gh-pages` 分支后，CDN 仍可能提供旧版本 10-15 分钟。
判断方法：直接看 `gh-pages` 分支内容是否已更新，
如果分支对了但线上还是旧的，就是 CDN 问题，不要反复改代码。

**用 bundle 哈希比对而不是只看页面能否打开。**

## 五、端口占用（Instabox 沙箱实例）

同一个沙箱里跑着多个项目，端口是有主人的：

| 端口 | 归属 |
|---|---|
| 8000 | 其它实验服务 |
| 8080 | 「一刀999 · 百图征途」（**另一个项目**） |
| 8090 | 其它实验服务 |
| 8964 / 18964 / 28964 | 其它实验服务 |
| 9090 | **本项目「霓虹心事」** |

**绝对不要用 `pkill -f 'http.server'`**，那会误杀别人的服务。
必须带端口：`pkill -f 'http.server 9090'`。

## 六、凭据管理

**含真实令牌的文档绝不能进仓库。** GitHub 有 Push Protection，
一旦推上去会被直接拦截（GH013），而且令牌已暴露在传输过程中。

正确做法：
1. 凭据文档写入 `.gitignore`
2. 需要给其它 AI 时，通过对话传递，不要靠仓库
3. 长期方案是模板 + 环境变量注入

当前的凭据文档：`docs/deploy-handoff-instabox.md`、`docs/deploy-handoff-prompt.md`，
两者都已在 `.gitignore` 里。

## 七、多远端一致性检查

四个远端（AtomGit / GitCode / Gitee / GitHub）：

```bash
for r in atomgit gitcode gitee origin; do
  echo -n "$r: "; git ls-remote $r -h refs/heads/main | head -1
done
```

推送用 `bash push_all.sh`（纯 ASCII 输出，曾因多字节字符出过 `unbound variable`）。
**GitHub 因为令牌文档被拦，会比其它三个少几个纯文档提交，代码无差异，可接受。**

## 八、部署后必做验收

```bash
curl -s <地址>/index.html | grep -oE 'v0\.[0-9]+\.[0-9]+' | head -1
BASE=<地址>/index.html node tools/live-check.mjs
```

要求：版本一致、bundle 哈希一致、`errors: []`、`failed: []`。
