# 02 · 剧情与内容开发

> 来源：v0.1.9 / v0.1.10 内容补齐、v0.9.2-v0.9.6 内容与可达性、三线通关实测结论

## 一、事件数据结构要点

事件都是数据对象，关键字段：

```js
{
  id: 'xxx',                    // 全局唯一，测试会查重
  trigger: { day: 4, hour: 9 },  // 时间触发
  // 或 trigger: { event: '某事件id', dayFallback: 5 }  事件触发 + 天数兜底
  // 路线过滤：trigger.soloOnly: true / trigger.inRoute: 'shenyan' 等
  messages: [...],              // 消息批次
  choice: { options: [...] },   // 选择
}
```

**选择项跳转**用 `choice.options[].effects.thenEvent`，
消息批次之间用 `message_batch` 的 `then` 链式串联。

## 二、时间推进机制

- `advanceTime(minutes)`：按分钟推进，**每次地点移动 +30 分钟**
- `advanceToNextDay(hour)`：直接跳到次日某点（玩家点"等到明天"时用）
- `_checkTimeEventsForRange`：补触发被睡眠跳过的小时
  —— 没有它，玩家一觉睡过去就会永久丢失触发窗口

**开发时最容易忽略的**：写了一个 `trigger: {day: 5, hour: 14}` 的事件，
如果玩家那天 13:00 睡到 18:00，靠 `_checkTimeEventsForRange` 才能补上。
但补触发仍然是"发现窗口被跳过"，不是"任何时候都会触发"。

## 三、内容可达性 —— 本项目最大的坑

**实测结论（2026-11-18 三线完整通关）**：结局在 **day8-10** 触发，
但 day11-21 新增了大量事件，**大部分根本走不到**。

原因：
1. 结局触发后 `gameEnded` 置位，后续时间事件全部不再调度
2. 路线专属事件写了 `trigger.inRoute`，但选了路线后玩家可能在别的日子就进了结局分支

**做内容前必须先算清路线长度**。判断一个新事件是否可达，按这个顺序查：

```bash
node tools/reachability.mjs    # 输出不可达事件清单
```

自查清单：
- 该事件 `trigger.day` 是否 ≤ 结局触发日？
- 如果是路线专属，该路线的玩家在这个 day/hour 是否还"活着"（没进结局）？
- 它与主线路链是否会在消息队列里抢时序？

**踩过的坑**：曾经想在 day4-6 补 14 条"空窗期"事件，
结果与南方出差/告白/危机/雨夜回程的路线链冲突，一次性挂掉 5 个剧情测试
（雨夜回程、半个月后、结局触发、游戏已结束、已记录结局）。
**结论：day4-6 根本没有空窗期，别往那儿塞。**

## 四、路线与调度隔离

v0.9.5 做的核心改造是**调度隔离**：线内事件移入"选线后窗口"，
避免未选线时就被调度、或者在错误的路线上触发。

路线专属事件写法：
- `trigger.soloOnly: true` —— 只有独行线可见
- `trigger.inRoute: '<路线id>'` —— 指定路线可见

改调度逻辑后**必须重跑 `npm run test:story`**（294 条断言），
这条链专门检测时序问题。

## 五、独行线内容偏薄

当前统计：沈砚之/陆辞/江屿各 6 条路线专属时间事件，**独行线只有 1 条**
（另有 17 个 `soloOnly` 链式事件）。

这是已知的内容短板，做内容扩张时优先补独行线。

## 六、每日事件密度不均

现状（v0.9.5 统计）：

```
day4: 5  day5: 5  day6: 6  day7: 8  day8: 5  day9: 6
day10: 2  day11: 8  day12: 3  day13: 4  day14: 3
```

day10 只有 2 条、day11 有 8 条，落差明显。
`validate:story` 还会警告 **day5 时间事件仅 1 条**（建议 ≥2）。

## 七、内容提交前必做

```bash
node validate_story.js      # 错误必须为 0
node test_story.js          # 294/294
node tools/i18n-gap.mjs     # 新增文案是否都补了英译
node tools/reachability.mjs # 新增事件是否可达
```

四个都过再提交，否则会留下难以追溯的时序问题。
